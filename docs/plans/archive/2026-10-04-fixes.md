### 07 统计口径与呈现

以独立的周期统计结构保留周期起止、指标名称及原始显示值，不再把这些字段塞进一段 label 后重新拆解；可在现有 `ReportModule` 上增加此模块所需的可选结构，不另造通用表格框架。采集、模拟数据、两端渲染和 HTML/JSON 导出在同一轮迁移，避免页面已修正而下载仍输出旧数字。

桌面优先采用以下结构，列按有依据的指标展示，缺失显示“—”：

```text
时间       阅读时长       阅读天数       读过       读完       笔记
2026-09    … 小时         … 天           … 本      … 本      … 条
2026-08    … 小时         … 天           … 本      … 本      … 条
```

移动端按月份分组，下面缩进展示该月指标；预览按最近的完整周期组截取，更多弹窗按同一顺序展示全部记录。上游新增或无法归入固定列的统计项保留原名及原始文案，在完整明细中可见，不静默丢弃。

- 阅读时长使用对应非重叠周期的 `totalReadTime`（秒），阅读天数使用 `readDays`；`readStat` 的统计名称与数量文案原样保留，只有已核实的名称才映射到固定列。即便数量文案出现小数、复合时长或其他格式，也不能因解析失败而丢行。
- `readStat` 的笔记摘要与“已读取划线/想法条数”分开。前者来自周期统计，后者受采集覆盖和文本类型影响；不拿累计笔记或已采集文字数量冒充周期总笔记。
- 本周跨月时按准确周区间展示一组，不归到周一所在月份；本月写明截至日期；最近 24 月和自然年按月份分组；全部历史仅展示已取得的全历史汇总，不伪造月行。标题随周期语义调整为“周期阅读统计”等合适名称。
- 同步核查共用周期标签与排序：目前模块 03 在本周/本月路径可能出现 `weekly`/`monthly` 标签，模块 06 累计曲线依赖周期顺序。修正共有周期来源时一并核验 02、03、06、07 与顶部总量，避免相邻模块继续使用不一致口径。
- 模拟数据按相同周期边界生成，阅读日、笔记和总量与示例自身的记录一致；缺少依据的读过/读完指标保持缺失，不能为凑满列生成互相矛盾的数字。

官方依据：[`readdata` 字段说明](https://github.com/Tencent/WeChatReading/blob/main/skills/readdata.md)。数值错误的最终原因需通过真实数据逐项对照确认；目前确认的是解析、建模和截取方式存在缺陷，不宣称已核对用户实际账面数值。

### 本地真实数据与线上示例

1. 本地开发专用路由仅由 `server/dev.ts` 挂载，绑定现有 `127.0.0.1` 服务；复用 `newCollector`、`advanceCollector`、`buildReport` 与现有请求预算、分页和错误处理，不另写一套统计逻辑。不依赖邮箱和数据库已配置，按现有采集批次展示真实进度。
2. 开发 Key 只从服务端 `.env` 读取，不使用 `VITE_*` 或前端构建注入。数据暂存在本地进程内存；不落入公开示例文件。重复访问同一范围复用临时结果，手动刷新才重新采集；切换范围或退出页面避免旧响应覆盖当前数据。
3. 两端示例页通过共享的数据来源逻辑选择本地真实数据或模拟数据，不能继续无条件调用 `createDemo()`。保留显式模拟模式用于已有 E2E 和空状态检查，避免检查默认读取个人数据。缺失或失效 Key 时明确提示，并提供手动切回模拟示例；不静默用假数据冒充真实联调成功。
4. 区分“位于示例路由”与“数据确实是模拟”。本地真实数据允许按需获取真实书籍详情，下载按真实报告标识；生产模拟示例不请求个人接口。更新两端现有 `isDemo`/`demo` 相关判断，避免详情被跳过、导出错误标成原创示例或笔记未采齐就下载。
5. Netlify 入口继续只导入正式 `server/app.ts`，不导入开发路由；`/api/demo` 保持公开模拟数据。生产和公开预览不能通过查询参数开启开发来源，即便误配开发 Key 也不应启用本地专用路由。
6. 实施后更新 `.env.example`、[development.md](../../development.md) 和 [data-contract.md](../../data-contract.md) 的来源说明；只记录变量名称、启用方式及公开契约，不写 Key 或真实阅读正文。公开示例可用公开书籍资料，个人阅读数值及笔记继续独立模拟。

### 项目字体：霞鹜文楷轻便版（已接入 v1.522）

字体采用用户指定的 [lxgw/LxgwWenKai-Lite](https://github.com/lxgw/LxgwWenKai-Lite)，字体家族为 `LXGW WenKai Lite`。上游提供 Light、Regular、Medium；本项目先使用 Regular 正文与 Medium 强调，CSS 字重按实际字体元数据声明，不将单个静态字体文件伪装为可变字体。替换现有混用的系统无衬线、宋体、Georgia 和通用 serif，保留它们作为必要回退；Vant 图标字体继续专用，避免全局覆盖破坏图标。

- **资源与许可**：固定上游发布版本或提交，字体随站点自托管，桌面与移动入口共享同一份资源及字体声明，不依赖访问者已安装字体。随字体保留版权声明及完整 [`OFL.txt`](https://github.com/lxgw/LxgwWenKai-Lite/blob/main/OFL.txt)，在 [third-party-notices.md](../../third-party-notices.md) 记录来源与版本；先接入官方文件，后续仅在实测需要时按许可做网页字体压缩。
- **覆盖范围**：首页、登录、设置、报告、书架、笔记、按钮、输入与选择控件、弹窗、数字、图表轴标签/图例/tooltip、页面品牌字标。两端建立一致字体变量，清理现有 `font-family` 和 `font` 简写中的局部覆盖；代码或凭据输入按内容需要保留等宽字体。
- **加载与排版**：采用 `font-display: swap`，字体未到达时仍可阅读与操作；加载完成后核验标题换行、长书名、数字宽度、控件高度与 Logo 中线。Lite 未覆盖的生僻字由系统中文字体补齐。图表在字体可用后更新文字测量与布局，避免首次用回退字体计算后出现截断或错位。
- **品牌与导出**：页面中的“阅纹”字标使用相同字体，字体确定后再修正第 10 项对齐；独立组合 Logo SVG 应嵌入字体或将字标转路径，避免通过 `<img>` 引用时丢失网页字体。HTML 报告内嵌所用字体与许可，确保离线查看和打印仍保留指定字体，图表 SVG 使用一致字体；JSON 数据结构不因字体变化而改变。
- **验收**：覆盖双端、明暗主题、常用与生僻中文、英文数字、长内容、字体加载失败及 200% 缩放；验证线上构建和 `/m/` 均能取得同一字体资源，图表与离线报告无漏用。记录字体下载体积与布局变化，在真实字体加载完成后再验收 select 和 Logo 对齐，不新增自动化测试代码。

### 计划复核补充：六项实施约束

本节补齐现有需求的实施边界，不增加新的产品模块；依据为本地代码静态检查，尚未记作已复现或已修复。

1. **混合单位一并修正。** 01「核心指标」与 07 有同类问题：目录将 01 单位定为“小时”，真实与模拟数据行均包含时长和阅读天数。两端卡片、更多弹窗和 HTML/JSON 按指标保留各自单位，不能仅移动卡片右上角单位就算完成。时长保留秒作为计算依据，最后展示时换算和舍入；跨期汇总不相加已经四舍五入的显示值。
2. **区分统计范围与更新时间。** 当前 `meta.generatedAt` 取 `state.createdAt`，代表采集开始，不是最近成功更新。页面顶部展示统计起止日；弹窗分别说明采集状态和确有记录的数据读取时间，缺失则不显示虚构时间。页面重绘或打开弹窗不应刷新数据时间，失败也不应标为成功更新；没有模块级时间记录时只说明报告采集时间。当前后端按整份报告刷新，本轮继续复用这个能力，不为每张卡片新增独立刷新接口。
3. **避免旧数据覆盖新状态。** 除快速切换范围外，还要覆盖真实/模拟切换、重试、刷新页面和报告缓存恢复。来源或范围变化时切断旧请求写回；新增周期统计或笔记位置字段后，旧缓存应兼容读取或明确引导重新采集。现有 `report.version` 是任务并发版本，`keyVersion` 是凭据版本，二者都不能判断数据结构兼容性。优先新增可选字段并检查所需字段是否存在；旧状态仍有原始统计时重新聚合，已丢失笔记位置时引导重采。只有不兼容地变更公开报告结构时才调整契约版本，不引入新的缓存系统；不能把不具备新字段的缓存直接当作新功能已取齐。
4. **模拟示例与现有检查明确分开。** 现有 Playwright 固定搜索“山野来信”，部分操作还依赖原生 select 和旧章节按钮结构，配置会通过 `reuseExistingServer: true` 复用 `pnpm dev` 服务。运行已有检查前必须确认服务处于显式模拟模式，不能误用正在读取开发 Key 的服务。更换公开示例书目和 shadcn/vue 控件后，依赖旧书名及旧 DOM 的断言可能不再适用；仍运行并如实记录具体失败，区分实现回归与需求变化导致的旧断言失配。遵守不修改测试的约定，以人工操作补充新行为证据，不跳过用例、不保留隐藏旧控件、旧书目或伪造旧文案来凑通过；人工验证不等同于 E2E 全部通过。
5. **真实书目与模拟文本不混淆。** 线上示例使用真实书名、作者和对应封面时，阅读数值与个人想法仍可模拟；原创演示文字必须就近标注“演示文本”，不作为该书真实划线或金句署名。顶部引文、精选、笔记卡片与导出保持相同标识；如要展示该书真实原文，必须另外核实文字及出处。缺少匹配封面时使用带书名的占位，不临时抓取同名书封替代。
6. **先接字体，再验收排版和导出。** 字体基础接入提前到 A 阶段，B 阶段的卡片尺寸和换行直接按新字体设计，D 阶段集中微调。HTML 单文件内每个用到的字体文件只嵌入一次，图表共享字体声明；生成 SVG 前等待所需字体可用并核对文字测量，防止导出图表已经用旧字体宽度排版。记录字体资源与最终 HTML 文件大小，同时保证缺字回退、离线可读和导出失败反馈。
