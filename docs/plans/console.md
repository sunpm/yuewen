共用依赖、版本策略和工具职责统一见[PC 与 console 共用技术栈](pc-refresh.md#stack)，请求与缓存遵守[共用数据流规则](pc-refresh.md#data-flow)。本专题只维护后台的接法与差异。

| 部分       | 决定与边界                                                                                                                                                             |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 框架与路由 | React + TypeScript + Vite + React Router，放入 `console/`；路由基址 `/console`，独立 HTML、路由树与样式；保持一个根包                                                  |
| UI         | antd + 按需 `@ant-design/pro-components`，优先复用 ProLayout、ProTable 等展示能力；组件主题使用 Ant Design token                                                       |
| 请求与状态 | TanStack Query 管理列表、详情、分页、修改和失效；ahooks 仅用于通用交互。局部状态用 React，确需共享时使用独立 Zustand store，不复制列表缓存                             |
| 表单与校验 | 与 PC 一致使用 React Hook Form + Zod；通过 Controller/useController 接 antd 控件，不再用 ProForm 或 Ant Design Form 维护第二套字段状态                                 |
| 样式与动效 | Tailwind 负责布局和间距，共用品牌变量与字体；扫描目录、CSS layer 与 reset 按[工程规则](pc-refresh.md#engineering)隔离。优先使用组件已有动效，确有需要才按需加载 Motion |
| 认证与接口 | 独立 Better Auth React 客户端；复用认证库的密码哈希、会话与 Username 能力，Hono 提供 `/api/console/*`；管理员接口逐次验证权限                                          |
| 工程       | 与 PC 共用兼容版本、Biome 与 `tsc` 规则，保留独立 Vite 配置和 JSX 检查入口；根构建依次写入 PC、H5、后台产物，`pnpm dev` 接入后台端口与同源代理                         |
| 测试       | 沿用 Vitest、Playwright，React 组件采用 Testing Library；Vue 用例保留原配置，确保 `.tsx`、后台 API 和新增 E2E 实际被发现和执行                                         |

后台列表固定采用受控数据流：Query 提供 `dataSource`、`loading`、分页总数，页面控制分页、排序与已提交筛选；ProTable 不配置 `request`，关闭内置搜索表单及可编辑表格表单，筛选与编辑交给 RHF。刷新按钮调用当前 Query 的刷新，写入成功后按资源失效；不使用 `actionRef.reload` 再建请求链路。普通表格没有 ProTable 特有需求时直接使用 antd Table，不自行封装通用 CRUD 页面生成器。分页和非敏感筛选允许用 URL 恢复，邮箱、用户搜索词与编辑草稿只在内存保留。

后台表单采用原生 `form` 与 antd 控件；`Form.Item` 如用于布局和错误展示，不配置 `name`、`rules` 或 Form store 收集同一字段。RHF 通过 Zod resolver 管理校验，显式适配 Switch/Checkbox 的 `checked` 和 Select 等控件的值；提交中防重复，服务端字段错误与 409 冲突反馈回表单。优先使用已有 schema 的纯校验部分，权限、归属和版本检查始终留在服务端。登录仍调用 Better Auth 客户端，其余业务提交使用 Query mutation。

2026-10-08 核对官方 [RHF Controller 文档源码](https://github.com/react-hook-form/documentation/blob/master/src/content/docs/usecontroller/controller.mdx)及 [ProTable 文档](https://github.com/ant-design/pro-components/blob/master/site/components/table.md)：受控组件和 `dataSource` 接法可以保留 antd UI 并统一状态来源。[Ant Design Pro](https://github.com/ant-design/ant-design-pro) 完整模板使用 Umi，继续只按需复用组件和示例，不搬入第二套构建框架。截图先验证 [html-to-image](https://github.com/bubkoo/html-to-image) 在本站 PC SVG 图表、字体和目标浏览器上的效果，失败可降级为无图反馈。C0 已锁定 antd 6.6.5 与 @ant-design/cssinjs 2.1.2（MIT），共用现有 React 19.3.0、Query、RHF/Zod；尚无 ProComponents 的使用需求，暂未安装。没有复制完整后台模板，来源见[第三方声明](../third-party-notices.md)。

## 超管与登录

- 首期仅一名超管，不做动态角色编辑器。后台采用账号密码登录；普通用户与游客无法进入管理接口，不提供公开管理员注册、提权或模拟用户登录功能。
- 本地 `.env` 预留 `CONSOLE_ADMIN_USERNAME`、`CONSOLE_ADMIN_PASSWORD`，账号与随机强密码由 Agent 确定，仅用于一次初始化或显式重置。实现时提供初始化命令：使用认证库创建账号、存密码哈希，重复执行不覆盖已有密码；重置必须是单独的显式动作并撤销旧管理会话。不在启动、构建或每次请求时自动创建/重置。
- 管理认证使用独立 Better Auth 实例及 `console_auth_*` 表映射，复用认证库而不重写密码算法；Username 所需的内部邮箱由初始化命令生成不可收信的保留地址，不承担用户邮箱或发信用途。后台禁用公开注册、邮箱验证码及邮件找回，恢复通过显式重置命令完成。前台邮箱用户表不承担超管身份，超管不计入用户列表。参考 [Username 官方文档](https://better-auth.com/docs/plugins/username)。
- 管理认证挂载在 `/api/console/auth/*`，客户端指定同一 `basePath`，使用独立 `CONSOLE_AUTH_SECRET`；配置可用性仅检查数据库、管理认证密钥与应用地址，不复用依赖 Resend 的前台 `authConfigured()`。初始化命令在不挂载 HTTP 的独立进程中启用认证库的账号创建能力，公开服务保持注册关闭；不能为初始化临时开放线上注册。管理会话禁用 Cookie 缓存，逐次核验数据库中的有效期和撤销状态。
- 管理会话通过独立名称的 HttpOnly / Secure / SameSite Cookie 保存；有效期初始为 8 小时，退出及重置立即撤销。Cookie 覆盖管理 API 路径，不能只设为 `/console` 导致 `/api/console` 不收到它；读取时只接受管理会话，不回退为前台 Cookie。复用可信来源校验与数据库限流，密码登录不依赖 Resend 可用。
- 删除用户、撤销连接等 C3 危险动作每次在同一请求内核验当前密码，服务端绑定目标/动作，并在提交前确认核验未超过 10 分钟；凭据重置仍只走专门命令；禁止删除唯一超管。所有管理数据响应 `no-store`，修改请求校验来源，登录失败不泄漏账号是否存在。
- `.env` 中的明文不进入 Git、文档、日志、`VITE_*` 或浏览器包；生产初始化在对应环境单独执行。开发与生产使用不同随机密码，不把本地预设误写成已上线账号。`.env.example` 仅在实现相应配置时添加空占位。

## 截图反馈闭环

### 提交流程

React PC 所有主要页面提供“意见反馈”，包括报告、书架和笔记；H5 保留原邮件入口，截图反馈推迟至未来重构。点击时默认自动截图当前网页，在反馈弹窗遮住内容之前记录页面和滚动位置并生成图片；默认包含当前已渲染页面内容，长页不额外加载更多笔记或触发采集，不截整台设备或其他标签页，也不要求用户自行上传图片。展示截图预览、问题描述、可选复现步骤与联系方式；用户可移除截图或重新截图。仅在用户点击提交后上传 R2，取消则清理内存中的图片。

截图前在离屏副本中遮蔽 Key、密码、验证码、邮箱输入和账号标识，不修改屏幕上正在操作的表单；反馈弹窗不入图。报告与笔记可能包含私人内容，预览处明确说明会发送哪些内容，允许去掉截图。不要自动附上完整报告 JSON、DOM、网络请求正文、Cookie 或存储快照。

跨域封面、字体未就绪、Canvas 污染、SVG/浏览器不兼容、压缩超限或截图超时，要明确显示“未能生成截图”，仍允许提交文字与环境；保留已有描述，避免无限重试。图片仅接受 PNG/JPEG/WebP，每条最多 1 张、压缩后不超过 1 MiB；前后端都限制尺寸与解码后像素量（初始上限 400 万像素）。长页在限额内等比压缩；若无法兼顾清晰度或浏览器画布限制，明确提示并可改截当前可见区域，不静默裁切或声称整页已截完。限制只影响附件，不阻断有效文字反馈。

成功必须以服务端保存回执为准，返回反馈编号；接口失败保留本页草稿，可重试。使用稳定 `requestId` 和请求内容摘要：同一次请求重复提交返回原编号，携带不同内容复用标识则拒绝；编辑内容后生成新标识。浏览器不持久保存截图或阅读正文。

幂等标识绑定提交者和规范化载荷，包含文字、诊断字段及图片字节摘要；重试复用首次生成的载荷，不因重截图或更新客户端时间改变摘要。账号/游客使用已核验身份；无有效身份的访客先通过 `POST /api/feedback/context` 取得仅限反馈的短期 HttpOnly 提交 Cookie（最长 24 小时），确认建立后才提交正文和图片，不创建阅读连接或账号。仅在同一提交上下文返回最小回执，不公开正文或附件；身份变化、Cookie 丢失或过期时拒绝用旧标识重新写入，提示重新确认，不静默换属主。删除反馈后保留不含正文的短期幂等墓碑至重试窗口结束，旧重试不能复活记录。有效重试不重复预留容量或扣减成功条数，但仍受请求频率限制。

### 用户归属与环境信息

| 信息     | 来源与约束                                                                                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 当前身份 | 服务端从有效账号/游客 Cookie 取得归属；记录账号 ID 或游客关联标识、当前 `guest/account/mock` 连接类型。客户端不能指定反馈属主；未连接访客也可提交，不为反馈强制建立阅读连接      |
| 双会话   | 同时存在两种 Cookie 时按现有 `X-Yuewen-Connection` 核验当前阅读属主，可另外记录有效登录账号；不能将当前游客报告归给另一个账号。会话已过期时降为未验证访客并标明原因              |
| 用户展示 | 后台按账号关联读取必要的昵称与邮箱，列表默认脱敏；不复制长期用户画像。游客关联随游客清理置空，仍保留“游客”类别；不保存 Cookie、token 或 Key                                      |
| 页面环境 | 路由名称、经过白名单筛选的路径/范围/视图、PC 入口、主题、视口、DPR、语言、时区、浏览器和操作系统可得信息、客户端版本；不采集书名、搜索词、原始完整 URL、完整 referrer 或硬件指纹 |
| 运行环境 | 服务端附上部署环境、构建版本、接收时间和本站请求关联 ID；客户端字段是不可信诊断提示。IP 仅用于必要的服务端限流，不展示或长期保存完整 IP                                          |
| 故障线索 | 仅带可选的本站错误码、失败阶段和已脱敏 requestId；不采集任意控制台、网络或上游响应。字段不可得记为未知，不猜设备型号                                                             |

“属主环境信息”在本计划中指反馈者的浏览器、系统与页面运行环境；服务端部署环境另列，不能混为一组或把用户可伪造信息用于鉴权。

反馈属主与可选的登录账号关联分列保存，示例是页面来源而非账号身份。用户列表反馈数量和账号删除只按核验属主计算；双 Cookie 下的游客反馈不随旁边登录的账号删除，辅助账号关联仅置空。游客到期或保存连接后，原游客反馈不自动转为账号反馈。首次提交时会话过期可提示用户以未验证访客重新确认；已有请求的重试保持原提交上下文，不能自动降级并再创建一条反馈。

### 接口、存储与后台处理

以下接口已实现，由 `FEEDBACK_ENABLED=true` 显式开启；生产尚未开放。实际载荷与错误语义见[反馈数据契约](../data-contract.md#feedback-api)。

| 接口                                                         | 用途                                                                                                                   |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| `POST /api/feedback/context`                                 | 各身份先取得最长 24 小时的提交上下文；访客另设 HttpOnly Cookie，不创建阅读连接；沿用 JSON 和 16 KiB 上限               |
| `POST /api/feedback`                                         | 有界 multipart 提交描述、环境 JSON 与可选截图；返回 `201` 和编号，幂等重试返回原结果；覆盖未连接、游客、示例和账号用户 |
| `GET /api/console/feedback`、`GET /api/console/feedback/:id` | 分页筛选与详情，默认不在列表查询中加载图片或整段环境 JSON                                                              |
| `GET /api/console/feedback/:id/screenshot`                   | 管理鉴权后读取私有图片，校验真实格式并设置类型和 `nosniff`，不提供公开附件链接                                         |
| `PATCH /api/console/feedback/:id`                            | 更新状态、分类和内部处理备注；版本冲突返回 409，不能改写用户原文与提交时间                                             |
| `DELETE /api/console/feedback/:id`                           | 删除记录及附件，写入不含正文的管理审计                                                                                 |

新增 `feedback` 与 `feedback_attachment` 元信息表；后者仅存服务端生成的 R2 object key、真实 MIME、字节数、校验摘要、上传状态和到期时间，不存图片二进制或 Base64。使用私有 R2 Standard bucket，不开启 `r2.dev` 或公开自定义域名。图片由 Netlify 函数有界读取、校验后通过 [S3 兼容 SDK](https://developers.cloudflare.com/r2/examples/aws/aws-sdk-js-v3/) 写入 R2，全程不写服务器磁盘。管理端读取经本站 API 鉴权后流式返回，不提供长期公开 URL；首期不增加浏览器直传、跨域 CORS 或预签名上传流程。

R2 与数据库不具备跨服务原子事务：先在数据库事务中预留幂等记录、容量和待上传附件 key，再写 R2，成功后按版本条件提交反馈为可见并返回回执。重试沿用相同 key 和内容摘要，不生成重复对象；R2 或最终落库失败不报成功，保留可重试状态，并清理废弃上传。后台不显示半成品。用户选择无图提交时须明确提示，按变更后的内容创建新请求，旧待上传记录到期回收。

删除反馈或账号时，先在同一数据库事务中撤销附件读取并保存对象删除任务，再删除业务记录；尝试删除 R2 对象，失败由现有定时清理继续重试，成功后移除删除任务。上传完成前若发生删除或到期，最终提交应失败并安排对象清理，不能恢复已删除反馈。24 小时以上的未完成上传及未关联对象按前缀和元信息对账回收；删除任务不随账号级联丢失，不引入外部队列。对象 key 不包含邮箱、用户名或其他个人信息，由服务端生成，不接受客户端指定任意 key。

C2 同步扩展已有 `DELETE /api/account`，与后台删除账号共用上述事务清理入口；现有仅依赖外键级联的删除不能清理 R2，不能等到 C3 才修补。该阶段一并建立最小 `console_audit` 与对象删除任务表，支持反馈处理、删除和失败重试；C3 再扩展管理动作。清理任务按条数、字节和执行时限分批执行，有界重试，R2 故障不能阻断阅读缓存与认证数据清理。开发/受控环境提供显式清理入口以验证到期和删除重试，不放开公开预览的清理权限。

整条请求初始不超过 2 MiB、描述最多 4,000 字、诊断 JSON 最多 16 KiB；平台请求体、执行时间和内存限制在真实部署核验。R2 降低持久存储占用，但此上传方案仍消耗函数请求/计算和读取带宽，需一起测量。

已仅为 `POST /api/feedback` 配置 multipart 和实际流量 2 MiB 上限，其他接口保留 JSON/16 KiB。反馈和管理路由挂在阅读连接鉴权之前，各自执行来源、限流和身份检查，不要求未连接访客或超管提供微信读书 Key。

初始保留上限：截图 30 天，反馈正文与诊断 180 天，管理操作审计 180 天；账号删除立即撤销其反馈/附件访问并按上述删除任务清理 R2，游客到期只解除短期关联。反馈告知文案单独说明保留期限，不套用阅读报告的 2 小时规则。到期由应用立即拒绝读取，定时任务批量清理；R2 [生命周期规则](https://developers.cloudflare.com/r2/buckets/object-lifecycles/)设为 30 天作为对象清理兜底，不把平台异步删除当成即时权限控制。数据库恢复不能恢复已删 R2 图片，显示“截图已删除/过期”，也不能重启已删除账号或附件访问。

单 IP 初始每 10 分钟最多 5 次；有效用户/游客每小时最多 10 次，并设全站每日 200 条、附件总量 1 GiB 的初始应用上限（含待上传预留与尚未删除对象）。共享计数、幂等与容量检查须适用于函数并发，R2 实际可用预算更低时取更低值。附件容量不足时明确提示可改为文字反馈，次数耗尽返回 429 和重试时间。R2 免费额度为账号共享，存储和读写请求分别计量，实际套餐与用量见[上线资源](release.md#resources)；不承诺无限免费。

后台状态为待处理、处理中、已解决、已关闭，提供时间/状态/来源筛选与内部备注。邮件 `isunpm@outlook.com` 仅保留为接口不可用时的人工联系兜底，不自动发信；邮件不算已提交工单，也不再是主反馈验收目标。首期不做用户工单中心、附件任意上传或自动外发通知。
