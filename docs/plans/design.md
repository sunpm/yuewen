## PC 端设计方案

<a id="visual"></a>

### 视觉方向

产品名为 **阅纹**，取“阅读留下的纹理”之意，用于呈现阅读习惯、时间轨迹与划线积累；标语为 **看见你的阅读轨迹**。产品以“个人阅读档案”为主线，使用中文排版、书籍封面和真实阅读轨迹形成辨识度。

Logo 将展开的书页抽象为三道连续曲线，以中轴连接，表现层叠书页和累积的阅读记录；末端一笔辅色对应个人划线。图形保持平面、清晰、可缩放，提供明暗与单色版本。品牌预览见 [brand/brand-preview.png](../../brand/brand-preview.png)，可编辑版见 [brand/brand-preview.svg](../../brand/brand-preview.svg)。

品牌浅色沿用纸白、橄榄绿、黄铜金与浅沙；深色已采用近黑页面与炭灰卡片，绿色作为强调色。具体颜色、按钮配对、辅助文字、浮层及双端变量映射统一维护在[现行设计规范](../design-system.md#theme-colors)，这里不重复色值表。设计调整仍需核验图表 tooltip、日历空格、树图边框和 Vant 表面。

图表从指定色板建立有语义的颜色映射；需要更多系列时，在既定色相内调整明度，并配合标签、线型与图案区分，不把四个品牌色直接当作任意数量分类的唯一编码。当前首次访问默认自动（跟随系统），同时提供浅色与深色选择；，具体行为见[自动主题与反馈入口](#theme-and-feedback)。公开页面、账号页、报告及下载样式共用品牌规则，离线 HTML 仍按现行规范使用浅色纸张主题。

已生成的品牌资产位于 `brand/`：`logo-mark-light.svg`、`logo-mark-dark.svg`、`logo-mark-mono.svg` 为独立图形；`logo-light.svg`、`logo-dark.svg` 为横向组合字标。图形不依赖字体；组合字标已采用霞鹜文楷轻便版字形转路径，同步 SVG 与 PNG 品牌预览。已检查双端常用宽度和明暗主题；200% 缩放仍待验证。

用户已明确：桌面现成基础控件优先采用 shadcn/vue 官方组件，不在业务页面用原生 HTML 和自写 CSS 重做控件，也不止于做成相似风格。按需引入组件源码到 `web/src/components/ui/`，复用现有 `components.json`，仅适配品牌变量、字体、尺寸和必要变体。页面构图、图表、书架与笔记内容排版独立设计；页面结构保留语义 HTML，组件底层的原生元素正常保留。移动端继续采用已确定的 Vant。

| 控件用途（含已完成替换的场景）               | 优先采用的 shadcn/vue 组件                                                         |
| -------------------------------------------- | ---------------------------------------------------------------------------------- |
| 周期、分类、排序、书籍来源、笔记类型选择控件 | Select；使用官方 Trigger、Content、Item 与 Value 结构及箭头布局                    |
| 查看更多、书籍详情、下载选项等业务弹窗       | Dialog；侧边详情确有需要时使用 Sheet，复用组件的焦点与关闭行为                     |
| 报告章节、登录方式切换、封面/列表切换        | Tabs 或 ToggleGroup，按实际切换语义使用；路由导航继续使用 RouterLink               |
| 裸写按钮、搜索框、复选框、表单标签           | Button、Input、Checkbox、Label；校对现有 Button/Input 与官方组件，保留业务所需变体 |
| 方法说明、画像依据的 details/summary         | Collapsible 或 Accordion；卡片完整数据统一进 Dialog                                |
| 数据明细表、状态、提示与加载占位             | Table、Badge、Alert、Tooltip、Skeleton，按实际用到的场景引入                       |

对应原文按[笔记、卡片与导航](report-experience.md#notes-and-navigation)直接完整展示，不采用折叠组件，也不保留展开/收起入口；此规则同步双端与相关 HTML 导出。

选择与弹窗分别遵循官方 [Select](https://www.shadcn-vue.com/docs/components/select)、[Dialog](https://www.shadcn-vue.com/docs/components/dialog) 结构；章节切换参考 [Tabs](https://www.shadcn-vue.com/docs/components/tabs)。组件一次只引入用到的部分，所需底层与图标依赖随官方组件接入，不自己重写键盘导航、焦点管理、弹层定位和选择箭头。现有表单业务逻辑继续复用；不因替换输入控件而额外引入整套表单或数据表框架。删除已被组件替代的全局控件 CSS，避免旧 `select`、`summary`、`button` 样式干扰组件。品牌配色、字体、间距、圆角和动效通过共享变量及组件变体统一。

后续涉及组件替换时，随对应功能验收以下三点：

- **值绑定与联动**：原生 select 的 `change` 逻辑迁移到组件实际的值更新事件；一次周期选择只启动一次采集，分类、排序和笔记类型仍即时生效。“全部”、未选择与空结果分别处理；清除筛选后控件和结果一致。保留书籍详情跳转笔记时的 `book` 参数、月份联动、浏览器前进后退和当前周期，不让 Tabs 的内容挂载策略意外清空状态或重复创建图表。
- **表单与语义**：保留 Label 与控件关联、`required`、输入类型、验证码格式、长度限制、自动填充、禁用/加载状态及错误提示；Enter 提交和显式提交按钮继续有效，其余表单内操作明确 `type="button"`。Checkbox 正确绑定布尔值，控制导出内容；链接仍使用 RouterLink 或锚点，避免 Button 包出嵌套交互元素。通过既有检查和人工操作核验，不新增测试代码。
- **主题与浮层**：补齐相关组件所用的 card、popover、input、ring、secondary、destructive 等语义变量及对应前景色，复用阅纹配色。检查通过 Portal 挂载的 Select/Dialog 内容仍继承明暗主题与字体，且层级、滚动区域、焦点边框、禁用状态和长标题正常。移除卡片内联数据表后，同步更新图表的辅助说明，避免仍提示用户“下方展开数据表”。离线 HTML 继续静态输出，不依赖 Vue 组件运行时。

桌面采用约 1200–1320px 的阅读内容宽度、12 列栅格与稳定的留白节奏。概览强调重点，深度报告按章节展开；内容不会被全部压进同尺寸卡片。项目统一使用用户指定的[霞鹜文楷轻便版](https://github.com/lxgw/LxgwWenKai-Lite)，包括正文、标题、引文和数值；通过字号、字重、行高与间距建立层级。统计数字优先启用等宽数字特性并核验实际支持，不能因为数字样式而无意回退整段中文字体。缺字及加载失败时使用系统字体兜底，详见[现行字体规范](../design-system.md#font)与[开发资源说明](../development.md#development-source)。

### 原创体验重点

1. **阅读轨迹视图**：将月度节律作为一条可探索的时间轴，选择月份后关联该周期的指标、可获得的书榜和笔记。月份联动是现有报告中的局部筛选，不把年度偏好自动当成月榜；没有对应月份的来源就说明不可得，具体完成判据见[首版补齐清单](product.md#first-release-gaps)。
2. **可追溯的阅读画像**：每条结论可以展开看到支撑指标或原文，让“关于你”的叙述有证据。
3. **可回顾的笔记**：笔记卡片突出原文与来源，长文本不截断关键内容；导出采用专门排版。

动效服务于状态和层级：筛选、图表更新、详情展开与页面衔接有一致反馈。建议常规过渡 150–250ms、章节切换不超过约 400ms；支持 `prefers-reduced-motion`。不以长入场动画阻挡输入，不强制劫持滚动。

<a id="layouts"></a>

### 图表与双端布局

- 统一单位、图例位置、tooltip、轴线和颜色含义；同一分类跨图表保持一致颜色。
- 日历、矩形树图、横向榜单分别处理密度；长书名可换行或展开，小区域用可访问提示补充，避免意外裁切。书架卡片按[两行书名规则](report-experience.md#chart-scope)允许省略，详情必须能读取全文；页面不得因内容撑宽而横向溢出，日历等明确设计的区域内横向浏览按[现行设计规范](../design-system.md)保留提示。
- 图表提供必要的统计含义、范围或缺失说明以及可访问的数据表；不强制每张卡片追加一句无信息的结论，不能只靠颜色传达差异。
- 书封失败时提供有书名的替代封面；数据缺失时保持布局稳定。
- 桌面入口主要验收 1920、1440、1280；独立移动入口检查 320、375、390、430，并检查 768 的平板使用情形。覆盖 200% 缩放、键盘操作和长中文标题；桌面缩放后的控件应保持可达。
- 移动端在 `web-mobile/` 以 Vant 独立布局、单列卡片和底部弹层实现，保留详细信息；不把桌面页面改为一套按断点切换的手机布局。桌面与移动入口保留相互访问方式。

## 自动主题与反馈入口

更新日期：2026-10-04。状态：三态主题和双端反馈入口已实施；本轮未调用浏览器，人工与投递验收待完成。用户已确认首次访问默认自动、反馈采用邮件，并提供可公开展示的收件邮箱；所需输入已齐全，不视为功能验收通过。

### 目标与现状

`client/useTheme.ts` 现已区分自动／浅色／深色偏好与实际明暗值，双端 HTML 首屏同步初始化；系统变化和跨标签偏好变动同步生效，已有明暗偏好保留。桌面用现有 Select，移动用 Vant ActionSheet，图表与 Logo 继续消费共享状态。`FeedbackLink.vue` 在桌面页脚及移动首页、设置、登录提供邮件和复制操作，复制失败显示手动选择邮箱的提示。

### 自动主题

- 提供“浅色”“深色”“自动（跟随系统）”三个明确选项，保留当前主题入口，打开后可以直接选择并识别当前选项。桌面沿用 shadcn/vue，移动沿用 Vant。
- “自动”按系统明暗偏好决定实际主题，页面打开期间系统变化也应生效；明确选定浅色或深色时不受系统变化影响。
- 首次访问默认自动，保留已有用户保存的浅色／深色选择。偏好保存在当前浏览器，不依赖登录；同源桌面与移动入口共用偏好。
- 首屏初始化与运行时遵循同一规则，避免先出现浅色再切深色；本地存储不可用时仍可在当前页面切换，系统偏好不可用时自动回退浅色。
- 页面、Logo、浮层、Vant 与图表随实际主题同步变化，不触发报告重新采集，不清空范围和已读内容。离线 HTML 与打印继续沿用浅色规则。

### 反馈入口

首版采用邮件反馈，收件邮箱为 `isunpm@outlook.com`，由用户提供并同意在反馈入口公开展示。提供“发送邮件”和“复制邮箱”；没有配置邮件应用时仍可手动联系，剪贴板不可用时允许选中地址手动复制。本站不新增反馈提交接口、工单后台、附件存储或处理进度。

- 入口统一命名“意见反馈”。建议桌面放全局页脚，移动端放“我的”页，并在首页和登录页补轻量入口；游客、示例用户和已登录用户都能访问，不把反馈限制在登录后的账号区。
- 接收产品建议和问题反馈；邮件主题可预填“阅纹意见反馈”，正文仅提供问题描述与复现步骤提示，内容由用户自行填写和发送；不预设处理时限或一定回复。
- 不自动附带 API Key、会话信息、阅读报告或笔记。打开邮件应用只表示进入撰写流程，不能显示“已提交成功”。
- 使用上述已确认收件邮箱，上线前验证实际送达。用户已确认验证码发信邮箱另行配置在环境变量中，与本邮箱不同；两类邮箱分别使用，不用反馈邮箱覆盖验证码发件人，也不因新增反馈自动设置事务邮件的 `Reply-To`，完整发信规则见[上线计划](release.md#naming)。

### 执行步骤与代码落点

1. 在 `client/useTheme.ts` 区分三种用户偏好与实际明暗状态，首次访问默认自动；同步双端 HTML 首屏初始化，兼容已有本地值。
2. 在 `web/src/layouts/default.vue` 与 `web-mobile/src/App.vue` 接入三选项主题控件；核验 `client/components/ReportChart.vue`、Logo 和 Vant 的同步效果。
3. 在桌面全局布局、移动 `Settings.vue`、`Home.vue` 与 `Login.vue` 接入入口及邮箱展示、邮件唤起与复制操作；主题与反馈可独立实施，反馈不依赖游客认证改造完成。
4. 按下列清单人工核验，按实际代码改动运行已有检查；不新增或修改自动化测试。实际结果写入质量记录，完成后同步现行设计规范与总计划。

### 验收条件与依赖

- [ ] 双端均可选择三种主题；首次访问默认自动，已有浅色／深色偏好不被覆盖；刷新、页面跳转及桌面／移动入口切换后偏好保留。
- [ ] 自动模式实时响应系统变化，手动模式保持选择；首屏、浮层、Logo 与图表主题一致，报告状态不受影响；存储不可用时切换仍可用。
- [ ] 双端反馈入口在游客、示例与登录状态下均可达；邮件指向已确认的真实收件邮箱，由用户发送一条人工验证反馈并确认送达；同时核验邮箱复制与手动复制兜底。
- [ ] 两个主题下控件文字和选中状态清楚，键盘可操作，触达尺寸至少 44 × 44 px；移动入口不被底部导航或安全区遮挡。

需求与收件邮箱已齐全，无需用户补充信息。邮件入口不依赖本站数据库或验证码发信服务；上线前仍需收件侧确认人工验证邮件送达。

## 设计收尾与交付

后续组件工作先核对现行实现，已接入的 Select、Dialog、Table 和字体不重复迁移。[设计规范的后续统一事项](../design-system.md#followup)纳入 P4：优先处理文字可读性、触达尺寸、模块部分覆盖标识，再核验字重、语义变量与浮层一致性。无关的样式清理不扩大当前功能范围。

2026-10-04 随报告展示验收实施：桌面窄视口布局、图表尺寸变化边界、双端模块部分覆盖提示及已有缺失原因；桌面 Select 与 Dialog 关闭入口、移动模块明细入口触达尺寸补齐至至少 44px。已完成部分尺寸、Chrome 200% 和弹层键盘操作核验，实际证据与剩余项见[质量记录](../quality-log.md)；本轮又接入自动主题、邮件反馈，并将既有 9–11px 辅助文字提升至 12px、600 字重归为实际提供的 500、补齐部分轻操作触达与共享遮罩；整个 P4 仍需人工证据。

- [ ] 对相关页面复核规范中尚未统一的项目，逐项说明已修正、已核验无须修改或仍待处理；旧截图只作当时证据，当前验收保留本次页面证据。
- [ ] 按上述完整双端宽度、明暗主题、200% 缩放、键盘和减少动效要求核验；报告专题中的 390/430 是当轮重点，不替代 320/375 和 768 的整体验收。
