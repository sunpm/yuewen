## PC 端设计方案

<a id="visual"></a>

### 视觉方向

产品名为 **阅纹**，取“阅读留下的纹理”之意，用于呈现阅读习惯、时间轨迹与划线积累；标语为 **看见你的阅读轨迹**。产品以“个人阅读档案”为主线，使用中文排版、书籍封面和真实阅读轨迹形成辨识度。

Logo 于 2026-11-12 按用户提供的《Logoicon 应用图标设计参考 · 64 例》及后续选择再设计为「书页＋纹路」。借鉴 02 的统一粗笔画、06 的重复秩序与 12 的构件/负空间控制，采用三道圆端弧线组成「层页」标志；不复制参考品牌图形。品牌预览见 [brand/brand-preview.png](../../brand/brand-preview.png)，可编辑图形源文件见 [brand/symbol.svg](../../brand/symbol.svg)。

同日按用户追加要求，参考 [codex-quota 图标生成源](https://github.com/sunpm/codex-quota/blob/main/scripts/make-icon.swift)与 [anki-reader 图标](https://github.com/sunpm/anki-reader/blob/main/public/icon.svg)的圆角底板和内边距，为层页增加绿色背景色块。背景与反白笔画写入 SVG 源头，统一生成侧栏、favicon 和组合字标，无额外页面容器。

用户已确认 PC 使用纸白＋墨绿，正文改为中性墨色，墨绿承担动作、选中项和数据强调；深色使用墨黑绿底与浅墨绿。具体颜色、按钮配对、辅助文字和浮层统一维护在[PC 设计系统](../../DESIGN.md#colors)。图表、词云及 PC 离线报告同步新色板，冻结 H5 保留原主题；共享 Logo 更新覆盖各入口，不改变 H5 或后台布局。

图表从指定色板建立有语义的颜色映射；需要更多系列时，在既定色相内调整明度，并配合标签、线型与图案区分，不把四个品牌色直接当作任意数量分类的唯一编码。当前首次访问默认自动（跟随系统），同时提供浅色与深色选择，具体行为见[自动主题与反馈入口](#theme-and-feedback)。公开页面、账号页、报告及下载样式共用品牌规则，离线 HTML 仍按现行规范使用浅色纸张主题。

品牌资产由 `brand/symbol.svg`、`brand/wordmark.svg` 与 `client/theme.ts` 的 pine 色板经 `pnpm brand:generate` 统一生成，完整清单和使用尺寸见[现行品牌规范](../design-system.md#2-品牌与标志)。图形和组合字标不依赖运行时字体。本批按总计划阶段 10 完成 PC 颜色和品牌同步，验收见[主题与层页标志记录](../quality-log.md#pine-theme-logo-2026-11-12)；历史双端与缩放结论不扩大。

PC 新实现采用 shadcn/ui 的 Radix 组件，按需引入到 React PC 的 `components/ui/`；现有 shadcn/vue 只作迁移前基线。保留阅纹品牌变量、字体、尺寸与必要变体，基础控件沿用官方的键盘导航、焦点和弹层行为。完整技术栈与分工见[PC 技术选型](pc-refresh.md#stack)；H5 的 Vant 控件不随 PC 替换。

| 控件用途                         | PC 优先采用组件                                       |
| -------------------------------- | ----------------------------------------------------- |
| 周期、分类、排序、来源和笔记类型 | Select                                                |
| 查看更多、详情、下载选项         | Dialog；需要侧边详情时使用 Sheet                      |
| 章节、登录方式、封面/列表切换    | Tabs 或 ToggleGroup；页面导航用 React Router Link     |

| 方法说明、画像依据               | Collapsible 或 Accordion；完整数据进 Dialog           |
| 明细表、状态、提示与加载         | Table、Badge、Alert、Tooltip、Skeleton                |

笔记原文仍按[笔记、卡片与导航](report-experience.md#notes-and-navigation)直接完整展示；精简对象为重复描述和元信息，不截断正文。迁移时只引入实际使用的组件，删除仅旧 PC 依赖的全局控件样式，保留 H5 使用的共享资源。

后续涉及组件替换时，随对应功能验收以下三点：

- **值绑定与联动**：筛选逻辑绑定到 React 组件实际的值更新事件；一次周期选择只启动一次采集，分类、排序和笔记类型仍即时生效。“全部”、未选择与空结果分别处理；清除筛选后控件和结果一致。保留书籍详情跳转笔记时的 `book` 参数、月份联动、浏览器前进后退和当前周期，不让 Tabs 的内容挂载策略意外清空状态或重复创建图表。
- **表单与语义**：保留 Label 与控件关联、`required`、输入类型、验证码格式、长度限制、自动填充、禁用/加载状态及错误提示；Enter 提交和显式提交按钮继续有效，其余表单内操作明确 `type="button"`。Checkbox 正确绑定布尔值，控制导出内容；链接仍使用 React Router Link 或锚点，避免 Button 包出嵌套交互元素。原有控件迁移通过既有检查和人工操作核验；新增 PC 反馈直接影响的回归按[本次测试授权](release.md#validation)补齐。
- **主题与浮层**：补齐相关组件所用的 card、popover、input、ring、secondary、destructive 等语义变量及对应前景色，复用阅纹配色。检查通过 Portal 挂载的 Select/Dialog 内容仍继承明暗主题与字体，且层级、滚动区域、焦点边框、禁用状态和长标题正常。移除卡片内联数据表后，同步更新图表的辅助说明，避免仍提示用户“下方展开数据表”。离线 HTML 继续静态输出，不依赖前端组件运行时。

桌面外壳与内容宽度按下节顶部导航布局确定；图表可在主内容区内使用网格，笔记与书架按内容选择列表或封面视图。项目统一使用用户指定的[霞鹜文楷轻便版](https://github.com/lxgw/LxgwWenKai-Lite)，包括正文、标题、引文和数值；通过字号、字重、行高与间距建立层级。统计数字优先启用等宽数字特性并核验实际支持，不能因为数字样式而无意回退整段中文字体。缺字及加载失败时使用系统字体兜底，详见[现行字体规范](../design-system.md#font)与[开发资源说明](../development.md#development-source)。

### 原创体验重点

1. **阅读轨迹视图**：将月度节律作为一条可探索的时间轴，选择月份后关联该周期的指标、可获得的书榜和笔记。月份联动是现有报告中的局部筛选，不把年度偏好自动当成月榜；没有对应月份的来源就说明不可得，具体完成判据见[首版补齐清单](product.md#first-release-gaps)。
2. **可追溯的阅读画像**：每条结论可以展开看到支撑指标或原文，让“关于你”的叙述有证据。
3. **可回顾的笔记**：笔记卡片突出原文与来源，长文本不截断关键内容；导出采用专门排版。

动效服务于状态和层级：筛选、图表更新、详情展开与页面衔接有一致反馈。建议常规过渡 150–250ms、章节切换不超过约 400ms；支持 `prefers-reduced-motion`。不以长入场动画阻挡输入，不强制劫持滚动。

### 图表与 PC 布局

- 统一单位、图例位置、tooltip、轴线和颜色含义；同一分类跨图表保持一致颜色。
- 日历、矩形树图、横向榜单分别处理密度；长书名可换行或展开，小区域用可访问提示补充，避免意外裁切。书架卡片按[两行书名规则](report-experience.md#chart-scope)允许省略，详情必须能读取全文；页面不得因内容撑宽而横向溢出，日历等明确设计的区域内横向浏览按[现行设计规范](../design-system.md)保留提示。
- 图表提供必要的统计含义、范围或缺失说明以及可访问的数据表；不强制每张卡片追加一句无信息的结论，不能只靠颜色传达差异。
- 书封失败时提供有书名的替代封面；数据缺失时保持布局稳定。
- PC 主要验收 1920、1440、1280、200% 缩放、键盘操作和长中文标题；窄窗与缩放后的控件保持可达。H5 完整宽度与物理手机专项暂停，仅保留共享改动所需的兼容检查。
- H5 保留 `web-mobile/` 的现有 Vant 布局与入口，停止新功能和布局改造。后台组件按[后台技术选型](console.md#stack)使用 antd，独立于 PC shadcn/ui。

## 按设备选择桌面或移动入口

状态：未实施，因 H5 冻结推迟至未来 H5 重构。当前保留 `/` 与 `/m/` 的既有入口行为，不增加自动分流或双端切换控件；下面规则保留为重构时的设计输入，届时按新路由与技术栈重新核对，不计入当前 PC/后台交付。

### 后续重构时的选择规则与导航边界

1. 优先级为显式 `layout=desktop|mobile|auto` → 当前浏览器保存的手动偏好 → 自动判断。两端提供“电脑版 / 手机版 / 自动”入口；仅保存界面偏好，不保存 Key 或阅读数据。恢复自动会清除手动偏好；存储不可用时让本次 URL 选择继续生效。
2. 自动判断优先使用可得的设备信号，手机进入移动版；平板以触摸能力和初始可用宽度辅助判断，初始默认 1024 CSS px 及以下进入移动版，其余进入桌面版。普通桌面设备不因窗口缩小或 200% 缩放强制跳端；无法判断时保留当前入口并提供手动切换。不引入指纹 SDK，不把 UA 判断当作身份或绝对准确的硬件识别。
3. 只在已知前台 HTML 首次启动、挂载和发起业务请求之前决定是否 `location.replace`；目标已经正确则不跳转。页面内旋转、缩放、窗口变化不自动重载；只改变页面内布局。手动切换通过显式目标和偏好覆盖判断，不能被自动规则跳回；保持同源 Cookie 与主题，恢复原报告而非创建新报告。
4. 为 `/`、`/demo`、`/login`、`/settings`、`/overview`、`/report`、`/shelf`、`/notes` 与 `/m/` 对应路径建立共享映射。保持合法的 `range`、`connection`、`view`、`book`、`month`、`source`、hash，以及现有保存意图/幂等请求标识；不通过清空 query 丢失用户操作。书名/搜索词等现有参数可在本站导航保留，但不向统计或反馈环境原样传递。
5. 登录 `returnTo` 等嵌套返回地址继续按现有白名单校验，仅映射本站对应端的合法路径，不接受外站或后台地址；请求标识不重建、不跨用户复用。登录取消与保存成功均回到正确连接和范围。端间切换可能重建客户端内存，必须使用现有服务端恢复链路，不能将内存报告写入持久存储来绕过恢复。
6. `/console`、`/api/*`、静态资源、下载文件、未知路径和错误页排除在自动分流之外。只靠前端入口分流，不缓存基于设备的全站永久重定向；PC 用户访问 `/m/` 时仍按同一优先级判断，明确选择移动版则保留。

## 自动主题与反馈入口

更新日期：2026-11-13。状态：三态主题已实现，PC 控件改为原生单选分段；反馈改为 GitHub Issue 预填与可选本地截图。代码与工程检查完成，主题紧凑默认布局和深色切换已观察；Chrome 因用户操作中断，主题键盘/焦点及反馈界面关键验收待补；H5 保留既有主题与邮件入口。

### 目标与现状

PC 的 `web/src/hooks/use-theme.ts` 与冻结 H5 的 `client/useTheme.ts` 区分自动／浅色／深色偏好和实际明暗值，双端 HTML 首屏同步初始化；系统变化和跨标签偏好变动同步生效，已有明暗偏好保留。PC 顶栏使用原生 radio 分段，只显示三种横排图标，保留悬停提示、无障碍名称、选中与键盘焦点；H5 保留 Vant ActionSheet。图表与 Logo 继续消费原主题状态；PC 反馈与 H5 邮件入口按下节分别维护。

### 自动主题

- PC 在顶栏直接展示自动/浅色/深色三项图标，使用原生单选，不显示文字；保留三项悬停提示与无障碍名称，自动项说明“跟随系统”；一次点击即可切换，Tab 与方向键沿用浏览器单选行为。图标 16 px、选中底色 28 px，整组按内容宽度排列且无底色/外框；每项保留 44 px 点击区域，选中与可见焦点采用现有语义 token；H5 保留现有 Vant 实现。
- “自动”按系统明暗偏好决定实际主题，页面打开期间系统变化也应生效；明确选定浅色或深色时不受系统变化影响。
- 首次访问默认自动，保留已有用户保存的浅色／深色选择。偏好保存在当前浏览器，不依赖登录；同源桌面与移动入口共用偏好。
- 首屏初始化与运行时遵循同一规则，避免先出现浅色再切深色；本地存储不可用时仍可在当前页面切换，系统偏好不可用时自动回退浅色。
- PC 页面、Logo、浮层与图表随实际主题同步变化，不触发报告重新采集，不清空范围和已读内容。离线 HTML 与打印继续沿用浅色规则。

### 反馈入口

PC 全局顶栏以文字显示“意见反馈”，宽窄窗口均不使用图标，打开 GitHub Issue 预填入口；可选截图先在本地预览/下载，用户自行附图并提交。公开性提示、页面环境白名单与截图规则统一见[反馈专题](console.md#feedback)。H5 保留原邮件入口，暂停更新。

前台不再维护重复的问题描述/联系方式表单，不依赖本站登录、反馈 API 或 R2；现有后台和反馈数据清理能力保留关闭。打开 Issue 草稿不等于已提交反馈。
