目标是游客配置自己的 Key 后完整查看与下载，只有主动保存连接才登录。先读[已核对现状与技术改动](#implementation)，游客查看与登录保存两阶段均已接入，下一步按[验收清单](#acceptance)补齐动态证据，不重复实现；[交付顺序](#delivery)保留为阶段边界。保存冲突、事务与幂等行为以[保存连接与报告保留](#save-connection)为唯一详细依据。本文代码路径均相对于仓库根目录。

已在 `server/connections.ts` 统一游客会话、归属和保存转换，`server/app.ts` 复用采集器，`client/useConnection.ts` 与双端页面保留显式连接；下一步执行真实登录与并发验收。数据库和加密配置是游客链路依赖，邮箱服务只影响按需登录。长期报告存档属于后续阶段，不纳入本次首版闭环。

## 游客使用与按需登录计划

2026-10-04 已实施首版代码，完整验收待完成。阅纹的核心价值是阅读可视化，用户提供自己的 API Key 后应能直接看到结果；只有主动保存到账号、长期云端存档或跨设备恢复账号数据才需要登录。下载文件与当前会话暂存不属于要求登录的范围。后续工作覆盖 PC 和共用 API、采集及导出逻辑；独立 H5 按[冻结规则](pc-refresh.md#h5-freeze)暂停更新，本文双端代码描述仅为已实现基线，H5 完整专项待重构，[笔记、卡片与导航](report-experience.md#notes-and-navigation)六项体验调整继续保留。

### 能力边界

| 能力                                             | 游客                                           | 登录后                           |
| ------------------------------------------------ | ---------------------------------------------- | -------------------------------- |
| 配置自己的 Key、生成报告                         | 支持，先验证后建立临时连接                     | 支持，可复用已保存的账号连接     |
| 概览、全部报告模块、书架、详情、笔记、周期与筛选 | 完整支持，沿用数据覆盖率及资源预算             | 同样支持                         |
| 取消、重试、刷新和有效期内恢复                   | 支持；重试须有剩余采集预算                     | 同样支持                         |
| HTML / JSON 下载                                 | 支持，不弹登录；沿用完整笔记选项及分页完成要求 | 支持                             |
| 当前会话临时使用                                 | 支持，到期或主动清除后失效                     | 支持，临时报告仍会到期           |
| 保存 Key、下次免填                               | 不提供长期保存，可主动登录保存连接             | 加密保存到账号，可跨设备复用 Key |

不把游客模式裁剪为仅概览或不能下载的体验；数据缺失、内容预算和部分结果按相同口径说明。首版准确使用“保存连接”或“保存到账号”，不以“保存阅读档案”暗示长期报告库已经存在。

<a id="journeys"></a>

### 用户流程与文案

1. **首次使用。** 首页主按钮为“查看我的阅读”，进入可供游客使用的 Key 配置入口；输入、显示/隐藏和获取 Key 链接复用现有控件，提交文案为“验证并生成”。验证成功后先展示取得的概览，再补齐报告、书架与笔记。未连接时直接访问个人页面也进入连接流程，不跳邮箱登录。
2. **临时使用。** 页面明确标记当前为临时连接，说明临时凭证与报告到期清理、可随时清除；保留主题、筛选、详情、重试、取消及下载。有效期内刷新恢复当前任务；页面关闭停止发起新批次，不承诺关闭即清除服务端数据。
3. **按需保存。** 报告页提供“保存连接，下次直接查看”，用户主动点击后才进入登录，并保留当前页面、统计周期、报告及保存意图。登录取消、失败或邮件不可用时，仍能返回尚有效的游客报告继续查看和下载。
4. **登录返回。** 无冲突时完成保存并返回当前报告，不要求重新输入 Key、不因登录重新采集。账号已有相同 Key 时复用凭证，但仍检查是否已有另一份有效临时报告。Key 不同或报告冲突时，在一次选择中说明实际影响：替换账号现有连接或报告并保存本次结果，或保留账号现状并继续临时查看。后者不执行本次归属转换，切换到账号原连接需用户主动操作；具体规则见 [保存连接与报告保留](#save-connection)。
5. **再次访问。** 有效账号会话及已保存 Key 可直接使用；登录已过期时可重新登录恢复连接，也可另行提供 Key 临时使用。游客会话过期或已清除则重新输入 Key，不把游客过期提示成“请登录”。

登录本身不等于同意覆盖账号 Key 或清除账号已有报告；只有此前明确发起的保存意图或当前显式选择才执行保存。存在冲突时说明会停止并清除哪类旧临时数据，不读取或展示其他登录会话的报告正文。保存失败不得丢弃尚有效的游客结果；响应结果不明时先查询原保存结果，不提前显示成功或误判游客连接失效。

<a id="implementation"></a>

### 已核对现状与技术改动

当前代码已拆分游客／账号归属。`server/connections.ts` 提供临时连接、状态恢复、共享限流、保存事务与回执；`server/db/schema.ts` 以排他约束保护报告归属，`0002` 迁移在开发配置数据库成功。客户端不再把未连接直接送往登录，双端统一走 Key 配置；只有主动保存连接才登录。

仍长期保存账号 Key。游客凭证和报告闲置 30 分钟、绝对 2 小时；没有历史报告库。保存转换不重置原期限或预算，稳定请求和原报告 ID 保存在非敏感返回参数中。完整实现契约见[数据契约](../data-contract.md#游客连接与保存转换)，实际 API 证据和未验证项见[质量记录](../quality-log.md)。

- **会话与存储。** 增加短期匿名会话及加密游客凭证，以受保护的 HttpOnly Cookie 标识；报告、笔记分页、详情、续期、重试与清除均验证归属和到期时间。复用 PostgreSQL、加密能力和临时清理，不为游客创建长期账号，不将状态仅放在函数进程内存中，也不新增 Redis 或队列。游客链路与邮箱配置解耦，数据库和加密服务仍是运行依赖。
- **权限与采集复用。** 将统一登录前提拆成按操作判断的会话要求：临时接入无需账号，个人读取接受有效游客或账号会话，账号保存与删除必须登录。游客与账号共用 `server/collector.ts`、`ReadingReport`、请求预算和导出逻辑，避免各自实现采集器；开发专用 Key 和 `/api/dev/*` 继续只用于本地，不作为生产游客凭证或路由。
- **来源与双端。** 在共用客户端增加明确的游客来源与连接状态，双端首页、设置、报告页和登录返回统一跟随当前连接。游客连接与账号 Cookie 同时存在时，保留用户当前选中的报告归属，不能仅因检测到登录就自动切换或覆盖另一份报告。调整账号必需错误处理，分别显示游客到期、账号登录到期、Key 失效和临时报告到期。
- **限流与清理。** 沿用 [采集与聚合](architecture.md#collection) 的采集预算及应用总并发，将创建匿名会话、验证 Key、报告生成和详情请求纳入共享限流；按会话及可信来源 IP 约束，反复新建匿名会话不能无限绕过。`netlify/functions/cleanup.ts` 同步清理匿名会话、游客密文和关联报告；请求到期立即拒绝，不等待定时清理后才失效。
- **数据处理说明。** Key 与正文不写入浏览器持久存储、URL、日志或导出凭证字段。界面如实说明服务端临时处理和到期清理，不声称“完全不经过服务器”或“绝不写入数据库”。主动清除连接立即停止访问和后续采集，已下载的本地文件仍由用户保留。

<a id="connection-selection"></a>

### 连接选择与恢复

游客会话和账号会话可以同时存在，报告页必须明确使用哪一份连接。个人页面用非敏感的 `connection=guest|account` 保存选择，双端导航、设置返回、范围切换及登录返回携带该值；它不包含账号、Key 或会话令牌。`source=mock` 仍只控制示例来源，不能用示例来源参数代替个人连接选择。

共享客户端向报告、采集、详情、恢复与清除接口发送 `X-Yuewen-Connection: guest|account`。服务端据此选择要验证的 Cookie，再执行归属、版本和期限校验；这个请求头本身不授予访问权。账号设置、删除账号和保存到账号等操作始终额外要求有效登录，不能通过选择游客绕过。旧客户端未传选择值时，仅在一种有效会话存在时兼容推断；两种都存在则返回需明确选择的状态，不默认读取账号报告。

页面没有显式选择时，先恢复仍有效的游客连接，其次使用有效账号连接，并通过 `replace` 补齐参数；这一步不回顶、不重新采集。已经显式选择的连接过期或失效时，显示该连接的真实状态，让用户主动重连或切换，不能悄悄改用另一份数据。普通切换会清空上一来源的页面引用并隔离迟到响应，不删除另一份尚有效的服务端临时报告。

保存转换确认成功后才将当前地址改为 `connection=account`，并继续使用服务端确认的原报告；取消登录或保留账号原连接时仍为 `connection=guest`。退出账号只撤销账号会话和相应临时报告，不删除同时存在的游客连接；清除游客连接也不删除账号 Key。两个操作在界面上分别命名。

保存意图与目标地址应随登录往返保留；只接受本站桌面或 `/m/` 下的有效目标路径，携带适用的 `range`、`view`、`book`、`month` 和 `connection`，不接受外站返回地址。请求标识与保存意图需要在登录页刷新后仍可恢复，但只保存非敏感标识；归属与冲突选择始终由服务端重新核验。

<a id="save-connection"></a>

### 保存连接与报告保留

游客保存到账号应作为一次可验证、可重试的归属转换，复用当前有效连接与报告，不直接调用现有“保存 Key 后清空所有报告”的前端动作。

**报告冲突处理。** 每账号最多保留 1 份有效临时报告，与 [采集与聚合](architecture.md#collection) 一致。本节仅规定游客转入账号；普通账号生成的同会话替换与跨登录会话确认见[报告生成与替换](architecture.md#report-replacement)。账号没有其他有效报告且 Key 无冲突时，按已发起的保存意图直接转换。账号已有另一份有效报告时，无论 Key 是否相同、报告是否已采集完成，都先显示“替换账号临时报告并保存本次结果”或“保留账号现状，继续临时查看”；Key 也不同时，在同一选择中说明将一并替换连接。选择替换后，事务内停止旧任务、撤销租约、清除旧临时报告，再转入游客报告；选择保留或取消时，两份报告继续按各自原归属和期限使用，不执行部分保存。相同 Key 仅复用凭证，不合并两份报告或重采本次结果。

**首次转换。** 服务端验证有效游客会话、当前登录账号、保存意图和凭证版本，并在事务中锁定相关账号、游客状态及报告，复核用户确认的目标。若待替换报告身份或账号凭据版本已变化，回滚并刷新冲突说明；普通采集进度变化不重复索要确认。事务同时完成必要的凭证写入、旧报告替换、游客报告归属转换和保存结果回执。写入账号凭证时按账号归属重新加密，不能直接复制绑定游客身份的密文；相同 Key 的有效账号凭证可复用。保留游客报告范围、结果、覆盖率、分页内容、采集游标及已消耗预算，转入当前登录会话。转换本身不续期：沿用游客会话与报告中更早的闲置到期时间，绝对期限取两者更早值；转换后用户操作仍可按 [临时报告与访问隔离](architecture.md#sessions) 延长闲置期限，但不能越过该绝对期限。

转换期间暂停相关采集推进，撤销旧执行租约并更新版本，使游客旧批次及被替换的账号旧批次均不能迟到写回。事务成功时撤销游客访问凭证；失败则回滚凭证、报告、租约及回执变更，原归属下仍有效的报告可继续使用。只有确认服务端转换成功后客户端才切换来源并清理旧引用。

被替换账号报告的原页面沿用[报告生成与替换](architecture.md#report-replacement)的失效提示和停止自动重建规则；游客转换已有的一次冲突选择即完成替换确认，不额外再弹普通报告生成的确认。

**响应丢失与重复提交。** 每次保存意图使用稳定的请求标识；同一登录账号与请求标识只对应一次转换，重复请求不得指向另一份游客报告或改变已确认的替换目标。先在有效登录身份下查询原回执：已有成功回执时返回原转换结果，不再次要求已撤销的游客凭证，不重写 Key、不清除新报告、不重新转入；没有回执时才进入首次转换流程，并在事务锁内再次检查回执后校验游客状态，保证并发请求取得同一结果。回执与转换同事务提交，仅保存归属、请求标识、目标与结果等必要元信息，不含 Key 或阅读正文，最长保留至转入报告的绝对期限，并随账号删除清理。报告内容仍执行登录会话、凭证版本及到期校验；报告已过期、被清除或连接再次变化时如实返回当前状态，不凭回执恢复旧数据。回执过期后仍拒绝使用已撤销的游客凭证重新转换。

若尚未提交转换时游客会话自然到期，不绕过期限恢复数据，也不宣称已保存；明确提示本次连接已到期，需要重新配置。若转换已成功但客户端未收到响应，按回执确认结果，不误报保存失败。正常有效期内的保存不要求重新输入 Key 或重采。

<a id="delivery"></a>

### 实施顺序与交付范围

| 阶段                  | 工作范围                                                                                       | 完成判据                                                                                                                              |
| --------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 第一步 游客完整查看   | 匿名会话与临时凭证、共享采集权限、双端接入、完整报告与下载、刷新恢复、清除与过期、游客限流     | 不配置邮箱登录服务也能从输入个人 Key 到查看、筛选、详情和下载；游客互相隔离，缓存和函数实例切换符合约定                               |
| 第二步 登录保存连接   | 保留邮箱验证码及可选密码、保存意图与返回、Key 与已有报告冲突选择、事务转换及结果回执、回访免填 | 登录后当前报告继续可用；不重填 Key、不重采、不静默覆盖；账号始终最多 1 份有效临时报告；响应丢失可确认原结果，取消或失败保留原有效结果 |
| 后续阶段 长期报告存档 | 登录后明确选择保存报告，独立于临时采集缓存维护历史报告列表、查看、删除及跨设备恢复             | 已保存报告不因临时会话过期而丢失，重新登录或换设备仍可查看；明确快照范围、采集时间、覆盖率与是否包含笔记，删除范围可验证              |

长期存档阶段开始前确定存储数量或容量、保留期限、完整笔记是否保存及默认值、重复保存规则和账号删除行为，再更新数据模型与界面承诺。保存连接不默认开启报告存档；首版不为后续阶段提前建立空的历史库、公开分享、付费层或定时后台采集。[笔记、卡片与导航](report-experience.md#notes-and-navigation)体验调整与本节共享页面时合并核验，不能因新增接入流程遗漏既有待办。

第一步可独立交付游客查看，第二步完成后再核验游客保存转换；不能用第一步通过替代整个专题完成。与报告体验计划共用的范围、导航、笔记分页和导出规则，在各自实现阶段先核验已有来源，游客与保存链路就绪后执行下列联合验收。

<a id="acceptance"></a>

### 验收清单

- [ ] PC 从未登录首页或个人页面进入，配置自己的有效 Key 后可查看全部现有模块、切换周期、搜索书架和笔记、打开详情及下载 HTML/JSON，全程不被强制登录。
- [ ] 游客与账号的下载均遵循[整份报告范围](architecture.md#export)，局部筛选不改变下载内容边界；保存转换前后统计范围、内容选项和覆盖说明保持一致。
