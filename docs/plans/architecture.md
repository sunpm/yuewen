## 技术架构与后端接口

<a id="structure"></a>

### 最小可部署结构

```text
浏览器：当前 Vue 页面；目标 React PC + 冻结 Vant H5，HttpOnly Cookie、内存报告
                  │ 同源 HTTPS /api
                  ▼
Netlify：静态前端 + Node.js Functions / Hono
                  ├── PostgreSQL：账号、认证会话、明确保存到账号的加密 Key
                  ├── PostgreSQL 临时表：匿名会话、加密游客 Key、任务进度与报告
                  ├── Resend：按需登录时发送验证码（建议）
                  │ 服务端按当前会话及凭证版本读取并解密 API Key
                  ▼
微信读书官方 Agent Gateway
```

单仓库、默认一个应用部署单元。当前主要目录如下，PC 迁移按[React 专题](pc-refresh.md)实施，后台另按[技术选型](console.md#stack)增加独立 React 入口；H5 保留但冻结：

```text
  web-mobile/          冻结的独立 Vant 移动页面与路由
  client/              既有 Vue composables 与可复用的纯 TS 图表、API、导出
  server/              本站路由、认证、Key 管理、微信读书适配、聚合和任务
  server/db/           数据模型、数据库连接与迁移
  netlify/functions/   Hono 函数入口与临时缓存清理任务
  shared/              前后端共用的必要数据类型
  docs/                数据契约、设计规范、开发说明与质量记录
  docs/plans/          目标方案、实施专题及历史归档
  AGENTS.md
  task_plan.md         目标、阶段、下一步与未完成项
  findings.md          发现、决策与专题索引
  progress.md          会话记录与验证摘要
  README.md

  netlify.toml
```

采用一个根包与明确的开发/构建脚本，在同一个 Netlify 项目部署静态前端和 Functions。已使用 PostgreSQL + Drizzle 管理模型与迁移，认证采用 [Better Auth 的 Hono 接入](https://better-auth.com/docs/integrations/hono)、[Drizzle 适配](https://better-auth.com/docs/adapters/drizzle)和邮箱验证码方案。复用同一数据库存放有期限的任务进度与分段报告，不依赖函数进程内存跨请求保存状态。暂不引入微服务、Redis 或单独队列服务。PC 与 console 统一 React Router、TanStack Query、必要的 Zustand、React Hook Form/Zod 和交互用途的 ahooks，职责见[共用技术栈](pc-refresh.md#stack)，缓存和提交规则见[共用数据流](pc-refresh.md#data-flow)。两端认证实例与运行时缓存独立；H5 保留现有 Vue composables。

阅读业务的数据库长期保存范围为认证库需要的用户、登录身份、会话与验证记录，以及用户明确保存到账号的微信读书凭证。每个本站用户最多一份凭证，记录密文、加密密钥版本、凭证版本、配置状态、更新时间、最近验证时间及必要失效原因。另用临时表保存匿名会话、加密游客 Key、采集游标、任务版本、执行租约和报告分段，按[临时报告与访问隔离](#sessions)到期拒绝访问并定期删除；游客不自动创建长期账号。临时表用于适配无状态函数，不等于向用户提供长期报告存档；下载文件不上传服务器。游客链路仍依赖数据库与加密配置，但不依赖邮箱或登录服务已配置。新增后台认证、反馈与管理审计按[后台计划](console.md)独立设定权限和保留期。用户主动提交的截图文件存私有 Cloudflare R2，数据库只存附件元信息，服务器不落盘；不把附件混入临时阅读报告或下载文件。

图表使用 [ECharts 按需导入](https://echarts.apache.org/handbook/en/basics/import/)，报告页面懒加载。现有 PC 使用 shadcn/vue + Tailwind，目标迁移为 shadcn/ui + Radix + Tailwind；继续由 Netlify 托管静态资源。后端以 [Netlify Functions 的 Request/Response 入口](https://docs.netlify.com/build/functions/get-started/)调用 Hono 的 `fetch`，在同源 `/api/*` 提供服务；使用 Node.js Functions，不照搬 Hono Netlify 教程中的 Deno Edge Functions 模板。请求边界执行运行时校验，响应按本站数据契约构造，不把 TypeScript 类型当作输入校验。

### 本站接口草案

以下是本站计划提供的正式接口，不是微信读书已有接口。认证库处理 `/api/auth/*` 下的登录、会话查询与退出。公开示例、健康检查和临时接入入口不要求账号登录；个人报告、采集和详情验证有效的游客或账号会话；账号凭证管理、保存连接及删除账号必须登录。从服务端会话取得归属，不接受客户端指定账号归属；游客模式不是将全部个人接口公开。微信读书 Key 仅用于服务端访问上游，不作为本站账号登录凭证。本地开发入口继续按[开发来源说明](../development.md#development-source)独立挂载，不能直接作为生产游客实现。游客接入、清除及保存转换接口已实现，见[数据契约](../data-contract.md#游客连接与保存转换)。

| 方法与路径                       | 输入/用途                                                            | 输出与行为                                                                                                                                                             |
| -------------------------------- | -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/account/weread-key`    | 查询当前账号的 Key 配置状态                                          | 仅返回配置状态、更新时间和最近验证时间等元信息，不回显明文或密文                                                                                                       |
| `PUT /api/account/weread-key`    | `{ apiKey }`；首次配置或替换                                         | 验证成功后加密保存并更新凭证版本；清除旧 Key 的任务和报告，不回显 Key                                                                                                  |
| `DELETE /api/account/weread-key` | 移除当前账号保存的 Key                                               | `204`，删除凭证、取消该账号采集、清除关联临时数据；保留本站账号                                                                                                        |
| `GET /api/session/reports`       | 刷新后查询当前游客或登录会话尚有效的任务与报告                       | 返回归属已核验的任务列表（任务 ID 为 `id`）；无缓存时返回空列表                                                                                                        |
| `DELETE /api/session/reports`    | 清除当前游客或登录会话的临时阅读数据                                 | `204`，取消任务并清除缓存；保留当前仍有效的连接及账号 Key；游客清除连接使用独立操作                                                                                    |
| `DELETE /api/account`            | 删除当前本站账号；要求近期重新认证                                   | 删除账号、关联 Key 和认证数据，撤销所有登录会话并清除临时任务与报告                                                                                                    |
| `POST /api/reports`              | `{ range, requestId, expected, replace? }`；目标及冲突字段见数据契约 | 校验当前会话和 Key，正常创建返回 `202`；其他登录会话已有有效报告时先返回冲突，按[报告生成与替换](#report-replacement)确认后创建；任务 ID 沿用 `id`，重复提交不重复替换 |
| `POST /api/reports/:id/advance`  | 推进一批采集，带任务版本和请求去重标识                               | 在函数时限内完成有限工作并保存游标、结果和进度；同一任务只允许一个有效执行租约，响应后由前端继续下一批                                                                 |
| `GET /api/reports/:id`           | 读取任务状态和已完成报告                                             | 阶段、实际进度、版本、覆盖率、已完成模块和可重试错误                                                                                                                   |
| `GET /api/reports/:id/notes`     | 按游标、书籍、类型、关键词读取已采集正文                             | 分页内容与当前覆盖范围；检索结果不能冒充未采集部分也已搜索                                                                                                             |
| `POST /api/reports/:id/touch`    | 当前报告的用户交互续期                                               | 验证归属与有效期，仅延长闲置期限；游客同步触达当前匿名会话，均不得超过各自绝对期限；返回 `204`                                                                         |
| `POST /api/reports/:id/retry`    | 剩余预算内重试可恢复失败或恢复已取消的采集                           | 保留成功结果、游标及已消耗预算；预算触顶时不再推进，提示查看或下载部分结果                                                                                             |
| `POST /api/reports/:id/cancel`   | 停止剩余采集                                                         | 返回可阅读的已有部分结果                                                                                                                                               |
| `GET /api/books/:bookId`         | 按需展开书籍详情                                                     | 元信息、可获得的进度与章节，避免初始化遍历查询                                                                                                                         |
| `GET /api/demo`                  | 获取公开示例                                                         | 模拟阅读记录及演示文本；书目与封面可用核验后的公开资料，`sampleReport: true`，不调用用户接口                                                                           |
| `GET /api/health`                | 部署健康检查                                                         | 只返回服务状态，不含会话或阅读数据                                                                                                                                     |

初版由前端串行调用 `advance` 推进分批采集，每次响应同时返回实际进度，不再另开高频轮询。`GET` 仅用于查询和恢复，不产生采集副作用；报告以版本号避免重传未变化结果，笔记正文分页返回。关闭页面后不保证继续采集，重新进入时在临时缓存期限内接着执行；页面明确显示这一行为。具体查询参数、错误响应和模块字段沿用已同步游客扩展的 [data-contract.md](../data-contract.md)，不按早期草案另建不兼容契约。

统一错误至少包含 `code`、中文 `message`、`retryable` 和无敏感信息的 `requestId`。账号专属操作未登录或账号会话过期使用 `AUTH_REQUIRED`（401）；游客未连接或临时会话到期返回独立、可识别的连接状态，引导重新配置而非强制跳转登录。两种会话的 Key 缺少或失效均使用 `WEREAD_KEY_REQUIRED` / `WEREAD_KEY_INVALID`（409），不混同账号登录状态。另行区分输入错误、上游限流、超时、部分失败与版本维护。只允许预先定义的上游接口和参数，不向浏览器提供任意网关代理入口。

退出登录由认证流程撤销当前登录会话，同时取消该会话的任务并清除临时报告，保留账号中保存的 Key。所有业务请求都验证会话，不能仅靠前端清空页面实现退出。

<a id="collection"></a>

### 采集与聚合

1. 首先验证当前游客或账号会话及 Key 配置状态，服务端按归属读取 Key，获取当前书架与首屏概览；首次配置时已经取得的数据供后续步骤复用。
2. 采集所选周期统计和笔记本概览，尽早完成概览、书架和基础图表。
3. 完整报告通过后续批次读取笔记内容，按书/页保存进度。第一屏不等待全量划线抓取完毕；函数不在 HTTP 响应结束后继续执行未受平台托管的任务。
4. 使用稳定 ID 去重；笔记本概览按 `lastSort` 分页，想法列表按 `synckey` 分页。检查游标是否前进，避免重复第一页形成死循环。
5. 单书失败记录到覆盖率，成功数据继续分析。筛选在已覆盖范围内优先本地执行。
6. 聚合完成后生成统一报告对象。前端展示和下载共用它，不维护两份计算逻辑。

报告对象沿用 `shared/report.ts` 的 `ReadingReport`：`meta`、`range`、`summary`、`modules`、`books`、`notes`、`portrait`、`coverage`、`issues`。时间、偏好与书架图表继续放在 `modules`，不新增并行的 `rhythm / preferences / shelf` 顶层结构。任务响应沿用 `client/useReport.ts` 的 `ReportTask`，包含 `id`、`version`、`keyVersion`、`status`、`stage`、`report`、`noteTotal`、`notesComplete`；任务字段不进入报告导出。运行状态采用 `queued / running / completed / partial / failed / cancelled`，模块状态沿用 `ready / empty / unavailable / partial`。`meta.source` 已包含 `guest`，共享类型、聚合与导出标识继续保持一致；`sampleReport` 继续兼容保留，来源标签不替代服务端归属验证。

游客扩展沿用当前已有预算：每账号或游客会话最多保留 1 份有效临时报告，包括采集中、已完成与部分结果；单批 1 次上游请求，25 秒租约、12 秒上游超时，全应用最多 8 个有效租约；每报告最多 600 请求、10,000 条正文、1.5 MB 采集状态。游客报告转入已有报告的账号时，按 [保存连接与报告保留](guest-access.md#save-connection) 明确选择后原子替换，不额外保留第二份有效报告。应用总量继续使用数据库约束，不依赖函数实例内存计数。游客接入、Key 验证、详情与采集另按匿名会话及可信来源 IP 限流，不能只限制账号，也不能把 IP 当作数据归属。重试保留现有用户触发行为，自动退避仍是后续优化。游标、去重和版本检查保证重复调用不会重复计数，清除连接、退出或更换 Key 后旧批次不能写回。

以上数值是本站初始配置，不是腾讯公布的配额。正式开放前按真实函数耗时和额度消耗调整；同时限制活动任务数、报告体积、正文数量和总采集时长。任一采集预算触顶时停止新增采集，明确显示限制原因与部分覆盖情况，保留查看和下载已有结果的入口，不提供能够继续本次采集的按钮。临时限流、网络失败及手动取消可在有效期和剩余预算内重试，重试与游客转入账号均不重置已消耗预算或延长原报告绝对期限。超预算分段续采另排后续阶段，首版不承诺取得超出预算的全部正文。笔记与报告分段返回，不触及函数响应大小限制。原计划核对的 Netlify 普通同步函数上限为 60 秒、缓冲请求/响应上限为 6 MB，实施和发布时复核[官方限制](https://docs.netlify.com/build/functions/configuration/)。

### 报告生成与替换

2026-10-04 普通账号替换流程已实现，当前配置数据库迁移成功，跨登录会话动态验收待完成；接口字段见[现行契约](../data-contract.md#report-replacement)。普通账号生成报告与游客保存转换均遵守每账号最多一份有效临时报告；前者按以下规则执行，后者继续以[保存连接与报告保留](guest-access.md#save-connection)为详细依据。

- **同一会话。** 当前游客或登录会话有同范围的有效报告时优先恢复；用户主动切换范围或明确重新生成时，可直接替换该会话的旧报告，不增加确认步骤。按服务端登录会话识别归属，不按屏幕尺寸或设备名称判断；同一浏览器的桌面与移动入口共用 Cookie，不算另一登录会话。
- **另一登录会话。** 同账号的其他登录会话已有有效报告时，无论范围相同与否，都先说明“继续生成会替换此账号在其他会话中的临时报告”，提供“替换并生成”和“取消”。取消不改动原报告，不启动新采集；原报告仍只允许其所属会话读取，不把确认流程变成跨会话恢复正文。仅提示存在冲突及替换影响，不展示书籍、笔记或报告正文。
- **确认与并发。** 确认绑定待替换报告的身份及账号凭证版本，服务端在事务锁内重新核验；目标报告或凭证变化时刷新冲突提示，普通采集进度变化不重复确认。成功替换时原子停止旧任务、撤销租约、删除旧正文并建立属于当前登录会话的新报告；失败保留原有效结果。沿用稳定的 `requestId` 处理重复提交，迟到的创建请求或旧批次不能覆盖最后一次有效选择。确认字段已写入[现行数据契约](../data-contract.md#report-replacement)，迁移沿用，不接受客户端自行声明归属。
- **原页面反馈。** 旧页面在下一次请求或恢复前台后的校验中识别“该临时报告已被替换”，停止推进和自动重建，清理失效报告引用。若用户主动再次生成，仍经过同样的冲突确认，避免两个页面反复自动替换。只保留供原会话识别替换结果的必要短期元信息，最晚随旧报告的原绝对期限清理，不保留其正文，也不延长报告期限。
- **作用范围。** 普通报告替换不修改账号 Key，不撤销其他登录会话，不转移其他会话的报告内容。没有其他有效报告时正常生成；已过期的报告不触发替换确认。新生成继续受共享限流和报告预算约束，替换不是继续超预算旧任务的入口。

主要落点为 `server/app.ts` 的创建、读取和批次接口、必要的数据库状态，以及 `client/useReport.ts`、`client/useReadingReport.ts` 和双端报告入口。随[报告体验验收](report-experience.md#chart-acceptance)核验同会话范围切换、跨会话确认与取消、确认目标变化、重复提交、迟到请求及原页面失效提示；游客保存转换另外执行游客专题验收，不把普通生成确认用于要求游客重复确认同一次保存。

## 账号、API Key 与下载

<a id="authentication"></a>

### 登录与持久化范围

首版个人阅读流程采用“游客配置 Key → 查看报告 → 按需登录保存连接”；示例、个人查看和本地下载均无需登录。登录的价值是长期保存连接并跨设备复用 Key；长期报告存档单独排在后续阶段，见[游客使用与按需登录计划](guest-access.md#guest-access)。用户已确认同一邮箱账号的双入口：验证码为默认方式，密码由用户自愿设置。认证使用 [Better Auth Email & Password](https://better-auth.com/docs/authentication/email-password) 和 [Email OTP](https://better-auth.com/docs/plugins/email-otp)，由 Resend 发送验证码。

推荐的具体流程：

- 新用户输入邮箱，通过验证码完成邮箱验证并创建账号，不强制设置密码；登录页明确告知首次验证会创建账号。
- 老用户可用验证码登录；设置过密码的用户也可选择“邮箱 + 密码”。两种入口返回同一个内部用户 ID，共用已保存的 Key 和设置，不增加独立用户名体系。
- 设置密码是账号设置中的可选操作，要求近期身份验证；忘记密码时通过邮件验证重置。密码哈希与验证交给认证库，不能沿用 API Key 的可解密保存方式。重置后撤销旧登录会话。
- 默认恢复尚有效的登录会话，无需每次访问都发送邮件；验证码有有效期、重发冷却和校验次数限制。两个登录入口均需限流。

选择依据：验证码减少初次使用的负担；可选密码让常用用户不必等待邮件，并减少验证码发送量。代价是需维护设置、修改和重置密码流程。原计划于 2026-10-03 核对的 Resend Free 额度为每天 100 封、每月 3,000 封，密码入口只能降低部分邮件消耗，新注册和找回密码仍依赖邮件，不能将其当作无限免费保障，见[邮件服务额度](https://resend.com/pricing/)。

账号、登录身份、认证会话和明确保存到账号的加密 Key 按账号策略保留；游客 Key、匿名会话和阅读报告仅进入带期限的临时缓存。本地下载和当前会话暂存不要求登录。首版不建设历史报告库，后续单独实现登录后的长期存档与跨设备恢复报告；不能将当前保存 Key 描述为已保存报告。

本站登录已使用数据库会话与 `HttpOnly`、`SameSite=Lax` Cookie，HTTPS 下启用 `Secure`。当前 `server/auth.ts` 配置有效期 7 天、更新间隔 1 天、近期认证窗口 10 分钟，禁用 Cookie 会话缓存；完整生命周期仍须按验收清单验证。刷新或重新打开页面时可恢复有效登录，已配置的 Key 无需重填；登录过期后重新登录，仍可复用账号中的 Key。登录期限与下文临时报告缓存期限分别管理，后台使用独立的[管理会话规则](console.md#admin-auth)。

配置 Key 时，经上游验证成功再使用服务端认证加密保存，例如通过 Node 标准库使用 AES-256-GCM。游客凭证绑定匿名会话并带到期时间；用户明确保存到账号后才成为账号长期凭证。加密密钥与数据库分开保管，凭证记录保存加密密钥版本以支持轮换；生产备份不把数据库与解密密钥打包存放。上游调用需要原始 Key，因此不能只存不可恢复的哈希。浏览器在提交成功后清空输入和明文引用，设置页仅显示配置状态与时间，不提供明文回显。

这是多用户服务，不将某个用户的 Key 写进生产环境全局 `WEREAD_API_KEY`。用户已提供一个本地联调 Key，保存在被 Git 忽略的 `.env` 中，文件权限为 `600`；只用于本地真实数据验证，已完成字段探针与一次有界本月报告采集。文档和 `.env.example` 不记录该值，前端构建与 Netlify 生产环境不注入该个人 Key。后端实施时另配置应用认证、数据库、邮件服务与 Key 加密密钥。

<a id="key-lifecycle"></a>

### Key 失效与重新配置

- 配置状态区分“未配置”“已配置”“已失效”，记录最近成功验证时间；“已配置”代表最近验证成功，不承诺一直有效。仅在上游提供到期时间时记录它，不自行推算 Key 有效期。
- 上游明确返回可识别的凭证过期、撤销或无效错误时，将对应版本的 Key 标为失效，取消该版本的剩余采集并停止自动重试，提示“微信读书 API Key 已失效，请重新配置”。上游错误映射在 P0 核实；普通网络错误、超时、限流、权限不明或 5xx 不直接判定 Key 过期。
- 提示提供“获取新 Key”和“重新配置”入口，游客不因此被要求登录；已有本站登录保持有效。已取得的部分报告可在原缓存期限内查看或下载，但不能继续请求上游。
- 新 Key 先验证，验证成功后原子替换当前连接并更新凭证版本，清除该游客会话或账号旧 Key 对应的任务与报告，重新加载数据。新 Key 验证失败时保留原配置及其原有状态。旧请求迟到的失效结果不能把新 Key 标为失效，旧任务也不能写入新报告。游客将同一 Key 保存到账号是连接归属转换，保留当前报告，按[游客使用与按需登录计划](guest-access.md#guest-access)处理，不能无条件走替换后的清空逻辑。
- 游客“清除连接”删除匿名会话的临时凭证、任务与报告；账号“退出登录”保留账号中已保存的 Key；“移除 Key”删除账号凭证并清除关联临时数据；“删除账号”再清除账号与认证数据并撤销全部登录会话。界面分别说明操作范围。

<a id="sessions"></a>

### 临时报告与访问隔离

阅读任务和报告保留在 PostgreSQL 的临时表，游客按匿名会话及 Key 版本隔离，账号按用户、登录会话及 Key 版本隔离，以适配 Netlify 无状态 Functions。初始缓存策略为闲置 30 分钟过期、最长 2 小时；游客临时凭证与匿名会话采用同样的短期边界。只有用户操作触发的访问延长闲置期限，自动采集与查询不无限续期，游客会话也不能因新建报告突破其绝对期限。每次读取和写回都检查到期时间，过期立即不可访问；定时函数分批物理清理临时凭证、会话和报告，删除和清理不依赖某个长期运行的进程。

页面刷新后查询当前游客或登录会话下尚未过期的任务与报告；若缓存仍在则继续显示并按游标续传。游客会话已清除或过期时需重新提供 Key，账号用户可使用已保存的有效 Key 重新生成。函数冷启动或实例切换不能导致有效任务与会话丢失。跨设备首版只复用账号 Key，不同步历史报告。关闭页面停止发起新批次，已发出的批次可能完成；不能承诺关闭页面即删除服务器数据，明确清除或到期才使其失效。退出登录立即撤销当前账号会话并清理其临时任务和报告。

浏览器不把 Key、可由脚本读取的会话令牌或阅读正文写入 localStorage、sessionStorage、IndexedDB 或 URL。游客及登录凭证均通过受保护的 HttpOnly Cookie 保存；清除连接、退出或普通账号切换时，只清空受该操作影响的连接与报告引用。游客与账号同时存在时的选择、刷新和退出行为见[连接选择与恢复](guest-access.md#connection-selection)。移除或更换 Key 后，其他页面在下一次请求时识别凭证版本变化并清空旧报告；将同一游客连接保存到账号时只保留经服务端核验归属的当前结果。

续期复用 `POST /api/reports/:id/touch`，由实际用户交互触发并节流；自动推进、查询和分页不触发续期。读取已采集报告、笔记分页和导出只要求归属、会话、凭证版本与报告期限有效；上游 Key 被标记失效时仍允许这些已有结果在原期限内使用。继续采集及未缓存的书籍详情需要有效 Key，不能因允许读取旧结果而继续调用上游。

- 每次读取或修改配置、报告、详情和任务，都核对当前游客或账号会话归属；账号专属操作额外要求登录。采用 Cookie 的状态变更接口校验可信来源并执行适用的 CSRF 防护。
- 全链路 HTTPS；私有接口和报告响应使用 `Cache-Control: no-store`，反向代理/CDN 不缓存它们。
- 日志不记录鉴权头、Cookie、Key 请求体、上游完整响应或笔记正文；只记录耗时、状态、数量和错误分类。
- 书名、简介、划线和想法按不可信文本安全渲染；导出 HTML 同样转义，跳转 URL 检查协议和可信来源。
- 为匿名接入、登录、验证码发送、Key 验证、详情与采集设置限流和资源预算；游客纳入共享限制，避免通过反复创建匿名会话绕过限制。
- 生产不使用真实报告作为静态构建产物、演示数据或自动错误追踪附件。用户主动预览并提交的当前页面反馈截图按[反馈规则](console.md#feedback)单独处理，不自动上传报告正文或完整数据。

### 首版建议下载格式

| 格式 | 内容                                                     | 实现原则                                                                                                                         |
| ---- | -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| HTML | 排版完整的离线阅读报告，含摘要、图表快照、来源与范围说明 | 浏览器生成单文件；ECharts 图表转为内嵌 SVG，作者排行使用静态 HTML 与内嵌 CSS 横条，均保留文字/表格；离线不依赖本站会话或远程脚本 |
| JSON | 聚合数据、范围、覆盖率和版本                             | 不包含 Key、会话令牌、内部诊断或未选择导出的原始数据                                                                             |

首版下载当前连接、当前统计范围对应的整份已采集报告，不受页面的月份联动、单书、分类、关键词、笔记类型、排序或当前章节等局部筛选影响。导出面板明确显示报告起止日及“下载整个统计范围的报告，不受页面局部筛选影响”；其中书架快照、累计笔记和年度偏好等例外继续标注各自实际范围，不能因“整份报告”文案抹掉部分覆盖。范围或连接正在切换、对应报告尚未就绪时，不允许误导出上一份结果。筛选结果的单独导出属于后续范围。

导出默认包含统计与报告已有的最多 20 条精选，可单独选择是否附上该报告全部已采集的详细划线/想法；首版不增加逐条手选精选功能。HTML 与 JSON 使用同一范围和内容选项。HTML 中外部封面优先使用文字替代，离线图表与正文必须完整；不为了封面引入任意图片代理。支持浏览器打印为 PDF 的基础样式；专门的 PDF 生成和笔记 PNG 卡片作为后续增强，不阻塞首版。

游客与账号用户均可下载，导出不触发登录。服务器不保存下载文件，不生成公开报告链接。下载到本地的文件由用户保留，不随本站会话退出或临时缓存到期而删除。

预算触顶后的报告可作为部分结果下载，文件保留覆盖情况与限制原因。下载前仍须补齐服务端已经采集的笔记分页；这是读取现有结果，不是继续请求上游，不受采集预算触顶阻断，也不能把分页已齐称为完整采集。
