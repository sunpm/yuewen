## 目标与已确认决策

做一个公开可访问的微信读书可视化网站：游客配置自己的微信读书 API Key 后，即可查看阅读概览、时间节律、阅读偏好、书架、划线与想法，并下载个人报告。查看、筛选、临时使用和本地下载均不要求登录；用户主动选择“保存连接，下次直接查看”时才登录，将 Key 加密保存到账号，后续使用自动读取。Key 过期或失效时引导重新配置。PC 是主要体验场景，独立移动端也应能够完成游客接入、查看、下载和按需登录。长期报告存档与跨设备恢复报告列入后续阶段，不阻塞首版。

## 参考站与资料结论

<a id="reference-site"></a>

### Booko Board 实际浏览记录

已打开[参考站](https://bookoboard.cookostudio.com/#top)，点击“先看示例”，查看仪表盘、封面墙、笔记墙，并切换浅色主题和笔记“小票”样式。

值得借鉴的是：明确的单一接入入口、无需 Key 的示例、清晰的顶部导航、大字号中文标题、克制的色彩、书封作为视觉内容、笔记重新排版后的可读性。本站将这些体验原则用于原创设计。

2026-10-03 浏览参考站时，示例的部分阅读指标显示为零或缺少数据，封面图片在所用浏览环境中也有未显示的情况。因此目前仅据此确认导航、布局与展示状态，不把示例值当作接口完整性或真实性依据。本站示例要覆盖完整报告，并使用相对当前日期生成的示例时间，避免切换到当前周期后只看到空面板。

<a id="gateway"></a>

### 接入方式

后端直接调用[微信读书官方网关规范](https://github.com/Tencent/WeChatReading/blob/main/skills/SKILL.md)，不要求网站访客安装 Skill 或运行命令。

- 网关为 `POST https://i.weread.qq.com/api/agent/gateway`。
- 上游鉴权为 `Authorization: Bearer <用户的 API Key>`。
- `api_name`、`skill_version` 和业务参数平铺在请求体顶层。
- 2026-10-03 查阅的官方文档版本为 `1.0.4`；开发接入时重新核对，集中管理版本。
- 检查 HTTP 状态和业务 `errcode`；上游要求升级时暂停相关调用，呈现维护状态，核实官方变更后更新适配。

yao-weread-skill 提供的是报告组织和分析思路。本站用 TypeScript 实现自己的采集与聚合层，不在 Web 请求中启动它的 Python 脚本。功能覆盖参考其[说明](https://github.com/yaojingang/yao-open-skills/tree/main/skills/yao-weread-skill)、[图表目录](https://github.com/yaojingang/yao-open-skills/blob/main/skills/yao-weread-skill/references/chart-catalog.md)和[数据契约](https://github.com/yaojingang/yao-open-skills/blob/main/skills/yao-weread-skill/references/data-contract.md)，字段含义以腾讯官方说明及实际回包为准。

## 用户流程与页面

主流程：进入首页 → 点击“查看我的阅读” → 输入自己的 Key → 验证并生成 → 获取概览 → 浏览报告 → 详细内容逐步补齐 → 下载。全程无需本站账号。公开示例与登录均保留为次级入口。

保存分支：报告页点击“保存连接，下次直接查看” → 邮箱登录 → 保存当前连接 → 返回当前报告；保留当前周期、已采集结果和进度，不要求重填 Key 或重新采集。账号已有其他 Key 或另一份有效临时报告时，明确选择替换并保存或继续临时查看，不静默覆盖。已登录且有有效 Key 的回访用户直接复用；Key 失效进入重新配置流程。完整转换规则见[游客使用与按需登录计划](guest-access.md#guest-access)。

页面共享当前游客或账号会话及已经获取的数据。示例切换到真实接入、切换账号或成功更换 Key 时清空旧阅读状态；游客将同一连接保存到账号属于会话转换，应保留已验证归属的当前报告，不能套用普通切换账号的清空流程。报告地址本身不包含访问凭证，也不作为公开分享链接；每次读取都验证相应会话归属。

首页先讲清楚“输入 Key 即可查看自己的阅读”；游客配置页说明“用于本次读取，临时凭证与报告到期清理，可随时清除连接”。用户主动保存时再说明“登录后将 Key 加密保存到账号，下次无需重填；当前报告仍会到期”。不能承诺数据完全不经过服务器，也不能将“保存连接”写成“保存阅读档案”。技术错误码、接口名、后台任务配置仅出现在开发诊断中，不进入普通使用流程。

### 状态设计

- 验证 Key 时立即给反馈；进入后先显示已经取得的概览，耗时内容分阶段填入。
- 展示实际阶段与数量，例如“笔记已读取 18/62 本”；总量未知时使用阶段状态，不伪造百分比。
- 分别设计正常、空账户、无笔记、字段不可用、部分失败、失效 Key、限流、超时、会话过期和服务维护状态。
- 区分尚未连接、游客临时连接、账号已保存连接及各自 Key 失效；游客会话到期引导重新输入 Key，账号登录过期可重新登录恢复连接，也可重新提供 Key 临时使用；微信读书 Key 失效提示重新配置，不混用会话到期与 Key 失效。
- 某一本书失败时保留其他成功结果；可以重试失败部分，也可以取消剩余采集并查看已有结果。
- 刷新页面后的会话行为见[账号、API Key 与下载](architecture.md#accounts-and-export)，接入时用简短文案说明。

三个画像内容模块分别为：基于指标的顶部阅读画像、来自实际划线的顶部金句、最多 20 条有出处的划线精选。它们在上述 27 个图表之外单独验收。画像文字初版使用可解释的规则与模板，注明由本站归纳；不默认调用收费大模型，也不把文字归纳描述为心理或人格测评。

划线精选最多展示 20 条，数量不足时如实展示。每条保留书名、章节（如有）和日期；区分划线原文与用户想法。顶部选句只能取自实际精选内容。词云使用可解释的中文分词、停用词和频次规则，不能把碎片词包装成准确的兴趣判断。

“更多”的实施方向已纳入计划，无需用户另列字段：增加日内阅读时段、自然日均与阅读日均时长、阅读活跃率、最长连续阅读天数、同口径周期变化、单书笔记密度，以及书籍详情和划线/想法的检索。首版在[采集与聚合](architecture.md#collection)预算内尽量采齐可获取内容，检索与导出仅覆盖已采集记录；预算触顶明确标记部分结果，超预算分段续采列入后续阶段。日历与连续阅读依赖完整日明细；笔记密度须标明分母及覆盖率；周期变化只比较范围和口径一致的数据。真实接口不支持的维度标明原因，不从汇总或 Top 列表推造明细。精选 20 条只是画像展示上限，不是笔记采集与检索的上限。

<a id="period-display"></a>

### 周期统计的展示验收

模块 07 的现行数据结构见[周期统计契约](../data-contract.md#period-statistics)。继续保留桌面的“时间 / 阅读时长 / 阅读天数 / 读过 / 读完 / 笔记”列，手机按完整周期分组；预览不能截断单个周期的一组指标，更多弹窗保留同序的全部记录。固定列只映射已核实的名称，其余 `readStat` 项保留原名和原文进入完整明细；缺失显示“—”，不把无法解析的复合时长或数量文案丢弃。

周期笔记摘要与已采集划线/想法条数分别展示；本周跨月仍是一组，本月写明截至日期，自然年和最近 24 月按月份，全部历史只显示已取得的汇总。核验 02、03、06、07 的周期标签、排序与顶部总量一致，模拟、双端及 HTML/JSON 不产生相互矛盾的数字。这些是持续适用的产品要求，不必到历史修复档案中查找。

### 首版补齐清单

已有模块和页面不等于首版覆盖全部验收。以下逐项核对现有实现，能用已有数据完成的直接补齐；数据缺失、范围不完整或来源不支持时展示原因并记录证据，不能填零、伪造或直接删除该维度。核验结果记录在[质量记录](../quality-log.md)，不得只勾选“计划已写”。

- [ ] 27 个模块和 3 个画像内容逐项有实际数据或明确的数据不可用说明；真实来源、模拟来源、明细、导出及缺失状态保持一致，顶部金句和精选有出处。
- [ ] 日内阅读时段采用正确的 6 点起始顺序；自然日均、阅读日均和活跃率按[固定口径](#extended-metrics)列明分子、分母及实际范围，不把未知阅读天数作为零。
- [ ] 最长连续阅读按每日满 60 秒与完整日明细计算；日历、阅读日与连续天数使用同一口径，缺日时不声称得到完整历史的最长连续值。
- [ ] 周期变化按[固定口径](#extended-metrics)比较当前报告内最近两个相邻完整自然月，显示两段日期；缺月、基期为零、只有本周／本月或全历史未采月桶时如实处理，不额外采集凑比较。
- [ ] 单书笔记密度使用同书同周期的已采集划线与想法数除以官方阅读小时，按[固定口径](#extended-metrics)处理重复条目、缺失日期、未读分页、部分覆盖、零时长及年度偏好与报告范围不匹配的情况。
- [ ] 月份联动只关联该月可定位的指标、书榜和笔记；没有该月书榜时说明不可得，不能将年度榜单改贴月份标签。画像依据可追溯，笔记检索和详情覆盖已采集内容。
- [ ] 预算触顶、单书失败、停止及 Key 失效后，仍能在原会话和报告期限内补齐已有正文分页并下载部分结果；采集覆盖与分页完整分别说明。
- [ ] 月份、单书、分类或关键词等局部筛选前后，下载仍使用当前统计范围的整份已采集报告；双端面板、HTML/JSON 及内容选项遵循[下载规则](architecture.md#export)，范围切换时不导出上一份报告。

### 扩展指标的固定口径

2026-10-04 明确，待实施或逐项核验。仅使用当前报告已经取得且范围可核对的数据，不为这些指标额外扩大采集预算。双端、画像依据、明细与 HTML/JSON 共用结果；主落点为 `server/collector.ts`、`shared/report.ts`、`shared/demo.ts`、双端报告组件及 `client/export.ts`。指标没有数据时保留名称与具体原因，不静默隐藏。

| 指标               | 首版计算规则                                                                                                                                        | 缺失与边界                                                                                                                                         |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 自然日均阅读时长   | 当前范围官方总秒数 ÷ 60 ÷ 范围内自然日数；显示分钟／天，起止日均计入，当前周期截至上海时区当天                                                      | 不计未来日期；总量或起止日未知时不可计算，不按“已取得日明细数”缩小分母                                                                             |
| 阅读日均时长       | 同范围官方总秒数 ÷ 官方有效阅读日数；显示分钟／阅读日，秒数统一除以 60 后展示                                                                       | 阅读日数未知时不可计算；实际 0 个阅读日显示“无有效阅读日”，不产生无穷大或将未知填零                                                                |
| 阅读活跃率         | 同范围官方有效阅读日数 ÷ 自然日数 × 100%                                                                                                            | 有效阅读日数覆盖完整且时间范围已核实后计算；实际 0 个有效阅读日为 0%，未知则不可计算                                                               |
| 最长连续阅读       | 已取得的完整日明细中，每日阅读满 60 秒算有效阅读日，按上海时区相邻日期求最长连续天数                                                                | 只描述当前实际范围；未取得的日期不补零、不算未阅读，日明细不完整时不输出完整周期的最长值                                                           |
| 周期变化           | 首版固定为月度环比：比较当前报告实际范围内最近两个相邻、完整自然月的官方阅读时长及有效阅读天数；变化量 = 本期 − 上期，变化率 = 变化量 ÷ 上期 × 100% | 排除尚未结束的本月；两个月必须均覆盖整月且所比较字段已取得，不跳过缺月改比更早月份。上期为 0 时保留变化量并说明基期为零，不计算百分比              |
| 单书已采集笔记密度 | 同书、报告所选时间范围内，按稳定 ID 去重的划线与想法条数 ÷ 同范围官方单书阅读小时；显示“已采集笔记／阅读小时”，小时 = 原始秒数 ÷ 3600               | 不含书签和想法引用中重复出现的原文，不使用累计笔记本总数。单书时长缺失、为零、只有格式化文字或范围不匹配时不可计算；不拿年度偏好替代最近 24 月时长 |

月度环比必须直接显示两个月份和各自完整起止日，不能让用户误以为在比较整个 24 月范围或本月与上月同期。本周、本月、全历史概览及其他无法取得两个月数据的范围显示“当前范围内没有两个可比的完整月份”；跨范围缓存或上一次报告不充当基期。月长不同属于自然月比较，展示真实天数，不伪装为等天数比较。按周、同月同期、年度或自定义基期比较留待后续。

笔记密度的分子必须来自创建日期可定位到该范围的已采集正文；日期缺失或上游采集不全时明确标为部分覆盖，仅解释为已采集条目的密度。尚未读取该书正文或客户端尚未补齐服务器已有分页时，不把暂时空列表算作零。实际已知为零可显示 0；计算前不四舍五入时长，展示值最多一位小数。自然日均、阅读日均及百分比同样只在展示时舍入，保留实际零值；不以高密度推断阅读质量。

<a id="ranges"></a>

### 首版建议范围

- 默认展示最近 24 个自然月，包含本月截至当天；开始日固定为最早月份的 1 日。页面写清实际起止日期，不使用含糊的“近两年”掩盖边界。
- 同时提供本周、本月、指定自然年、全部历史概览。全部历史不意味着自动逐日抓取所有历史数据。
- 采集方案沿用已实现的逐月采集，覆盖月度统计与日明细；排行和偏好优先使用匹配所选周期的回包，全部历史复用 `overall`，不为本周、本月、指定年或全部历史额外请求不匹配的结束年份。`recent` 的年度补充是下项明确规定的例外。偏好请求不加入时长总量。完整年汇总加边界月的请求优化留在后续，不作为报告体验调整的前提。不得重复累计重叠年月。
- 偏好字段有截断与展示阈值。全部历史使用官方全历史字段；本周、本月和自然年使用对应周期字段，缺失时如实说明，不回退为当年数据。最近 24 月采用明确标注的年度补充，其他年份通过已有自然年选择器查看；实际年度、请求及展示规则统一见[时间范围、数据来源与路由](report-experience.md#range-routing)。不能把各年/各月 Top 列表相加后宣称得到完整区间排行。
- 书架始终标为“当前书架”。笔记概览总量标为“累计笔记”；按创建时间过滤的明细另标为“区间内已读取内容”。
- 自定义任意起止日期作为后续扩展；首版把自然周期和明确的 24 月范围做好。

### 必须固定的数据语义

| 项目             | 规则                                                                                |
| ---------------- | ----------------------------------------------------------------------------------- |
| 时间与日期       | 内部保留秒和标准时间戳；展示按 `Asia/Shanghai`，时长转换为小时/分钟                 |
| 周期总量         | 完整周期取 `totalReadTime`；日/月明细用于图表。明细不完整时不能用其合计覆盖官方总量 |
| 阅读天数和平均值 | 区分有效阅读日与自然日；自然日均和阅读日均必须有不同名称及分母                      |
| 阅读时段         | `preferTime` 从 6 点排到次日 5 点，不能按数组下标直接当 0–23 点                     |
| 作者/分类        | 作者格式化时长不当数值处理；偏好权重不等于百分比；缺失偏好不代表零偏好              |
| 书架计数         | 电子书 + 有声专辑 + 非空文章收藏入口；文章收藏只算入口，不能冒充文章数量            |
| 笔记计数         | 划线 + 想法/点评 + 书签；可展示/导出的文本条数可能少于统计笔记数                    |
| 阅读进度         | 进度是 0–100；`1` 表示 1%。不把有声内容的完结状态当作用户读完                       |
| 空值与零值       | 未返回、未采集、采集失败和实际为零是不同状态；不一律填 `0`                          |
| 活动记录         | 书架最近阅读时间只是最近活动，不构造完整阅读事件流，不据此推算单本时长              |
| 画像与文本       | 保留原文与来源；只显示可获得的内容，不补写原文、不导出书籍全文                      |

规则依据：[阅读统计](https://github.com/Tencent/WeChatReading/blob/main/skills/readdata.md)、[书架](https://github.com/Tencent/WeChatReading/blob/main/skills/shelf.md)、[笔记](https://github.com/Tencent/WeChatReading/blob/main/skills/notes.md)、[书籍与进度](https://github.com/Tencent/WeChatReading/blob/main/skills/book.md)。

每个模块返回 `status`、`scope` 和 `coverage`。`scope` 区分请求范围、实际范围、偏好统计周期和快照时间，不固定写成自然年；`coverage` 至少记录应读取/已读取/失败的书或页数、是否完整以及缺失原因。日期近似或榜单截断必须在界面和下载文件中保留说明。

## 需求完整度与后续输入

核心需求已经足够完整：游客完整查看与下载、按需登录保存 Key、至少覆盖参考技能的全部数据、前后端方向、Netlify 部署和 Cloudflare DNS 均已有依据，本地联调 Key 也已提供。用户已指定明暗配色并授权品牌命名与 Logo 生成，产品名采用阅纹，品牌资产见[视觉方向](design.md#visual)；这些不再列为待补信息。无需用户再次列数据字段或重复提供 Key。真实接口覆盖、统计口径、分批采集成本和邮件投递效果由实施验证解决，不转化为要求用户解释的需求缺口。

登录组合已确认，详见[登录与持久化范围](architecture.md#authentication)：默认验证码、密码可选。其余产品偏好可先采用下表默认值，用户有明确偏好时再调整，不要求逐项作答：

| -------------- | ------------------------------------------------------------------------------------------------------------------- |
| 统计范围       | 最近 24 个自然月；提供本周、本月、指定年和全部历史概览，标明实际覆盖范围                                            |
| 下载形式       | HTML + JSON，提供基础打印样式                                                                                       |
| 画像解读       | 首版基于真实数据的规则摘要；收费模型解读不默认加入                                                                  |
| 登录与报告保留 | 游客凭证、匿名会话和临时报告闲置 30 分钟、最长 2 小时；账号登录 7 天；刷新复用有效缓存，保存 Key 不等于长期保存报告 |

网站域名、Neon 项目及数据库、邮件发信域名与发件人规则见[域名、云资源与邮件命名](release.md#naming)。用户已确认验证码发信邮箱配置在环境变量中，与意见反馈邮箱不同，不再要求重复提供。首次访问默认自动、邮件反馈及公开收件邮箱也已确认，具体范围见[主题与反馈计划](design.md#theme-and-feedback)。后续只在实际联调缺失时补齐相应服务配置与操作权限：
